HOW IT IS SOLVED
THE DEALER
Dealer probabilities come from a recursion on the dealer's next card. Every final total, 17 to 21 or bust, gets an exact probability for each upcard.
THE PLAYER
Each hand is a state: hard total, ace, and whether it is still two cards. Hitting always adds a card, so each state depends only on larger totals. Backward induction then gives each move's exact value.
THE LEARNER
Monte Carlo control never reads the probabilities. It plays hands, keeps a running average of what each move paid, and mostly takes the best move so far, with some exploration.
GAME LOG

HOW IT WORKS

Two methods, both on the same rules. The advisor and the basic-strategy table come from an exact solver: dynamic programming over every hand the player can reach, in an infinite-deck model. The Monte Carlo learner starts knowing nothing. It plays simulated hands and averages what each action paid, and its table is then compared with the exact one. It is never trained on that table.

Dynamic programming (exact)

New to this? Picture a maze solved from the exit backwards. Once you know the value of every spot next to the exit, each earlier choice is a simple comparison. Blackjack fits this shape: a hit always adds a card, so every hand you can reach depends only on hands with a higher total. The solver fills in values from the end of the game back to the first two cards.

The dealer's final-total probabilities come from a recursion on the dealer's next card, for each upcard. For each player state (hard total, whether it holds an ace, two cards or more) the solver computes stand, hit and double, and for pairs also split. The table has 33 rows (hard 5 to 19, soft A,2 to A,9, and ten pairs) by 10 upcards, 330 cells. The advisor uses the same values.

  • The dealer's blackjack peek is applied last. With p the chance of a dealer blackjack, each value becomes -p + (1 - p) × v. That map is increasing, so the best action does not change.
  • Split is exact because the infinite deck makes the two hands independent: its value is twice the average of one hand's best play.
  • Under this model, perfect basic strategy has a house edge of 0.570% of each bet.

Monte Carlo control (the learner)

New to this? Say you are new to a city and want the best restaurant. You try a few, keep a running average of how each meal went, and mostly go back to the highest average while sometimes trying something new. You never look up a guide. You learn from results alone, and the occasional new try keeps you from missing a better option.

LEARN plays simulated rounds on the server with a fresh random seed. It never reads the probabilities or the solver. Each round starts from a random table cell, so rare starts still get played. The learner credits each decision with what the hands it affected paid, and keeps a plain average per action. Stand, hit and double share estimates by upcard, hard total and ace flag. Split has one estimate per pair.

  • No discounting. The only reward arrives when a round settles.
  • Only the first decision of a round is chosen uniformly among legal actions. Later decisions are epsilon-greedy, and an untried action counts as worth 0.

How these were chosen: the rules are fixed choices, not learned, set to match the TABLE RULES panel. The 6-deck shoe and 75% reshuffle point are the defaults of the shoe class. The exploration constants (start 0.2, floor 0.01, the 2,000-hand scale) and the 0.01 decisive margin were set by hand. The repository has no sweep over them. The exact solver assumes an infinite deck, so the table is basic strategy for that model, and the shoe is where the measured result departs from it.

Training

Training is simulation only. Each run starts with empty statistics and no stored model. The page takes 16 snapshots during a run. With seed 1, after 40,000 hands the learner agrees with the exact table on 72.6% of the 321 decisive cells (mean value lost per cell 0.039). After 100,000 hands it agrees on 78.2% (0.023 lost). Agreement rises slowly as hands increase. Simulating exact basic strategy through the 6-deck shoe for 200,000 rounds (seed 1) gives -0.66% ± 0.26% per unit bet, close to the 0.570% infinite-deck edge. No committed result file covers Blackjack, so these figures come from re-running the code.
