HOW IT WORKS

The problem is the multi-armed bandit: a row of K slot machines, each called an arm, with payouts the player cannot see. Each pull chooses one arm and receives its reward, so every pull spends reward to learn more. Seven agent types are implemented, and each casino runs five of them (Bernoulli and Gaussian) or seven (drifting). Each agent sees only the reward of the machine it pulled. None is trained: every run starts from scratch and learns from rewards alone. The page runs a JavaScript port of the Python agents, which reproduces the same pulls for a given seed.

The casino and regret

A casino has K machines. The benchmark uses K = 5, and the page offers 2 to 10. Its outcomes follow one of three payout models. Bernoulli machines pay 1 with a hidden probability pi and 0 otherwise. Gaussian machines pay their mean plus noise, a random error, with standard deviation sigma = 0.2. Drifting machines are Bernoulli machines whose probabilities are redrawn every 500 pulls, so the best machine can change1.

Each mean is drawn uniformly from the interval [0.1, 0.9]. The draw is repeated until the best mean leads the second best by at least 0.05 (GAP), so that the best machine can be identified. The draws are made once per segment: one segment covers the whole game for stationary casinos, and a new segment starts every 500 pulls for drifting ones2.

\mu_i = 0.1 + (0.9 - 0.1)\,u_i, \qquad u_i \sim \mathrm{Uniform}[0, 1)
32

Here \mu_i is the mean of machine i, its expected reward per pull, and u_i is one uniform draw. The constants 0.1 and 0.9 are the code's LOW and HIGH.

2 
function DRAW-MEANS(K):
    while true:
        for i in 0 to K − 1:
            μ[i] ← LOW + (HIGH − LOW) × UNIFORM()
        if max(μ) − second_max(μ) ≥ GAP:    # the best leads by GAP
            return μ
function DRAW-MEANS(K):               # LOW = 0.1, HIGH = 0.9, GAP = 0.05
    while true:
        for i in 0 to K − 1:
            μ[i] ← LOW + (HIGH − LOW) × UNIFORM()
        ordered ← sorted(μ)
        if ordered[K − 1] − ordered[K − 2] ≥ GAP:
            return μ

The outcomes are rolled before play, one per pull and machine, from a separate random stream. The stream is seeded with the casino seed plus 1,000,003, so it does not share numbers with the machine draws4. Each stored number is called the luck l_{t,i} of pull t on machine i. A Bernoulli machine pays when its luck is below its current probability, which gives the correct chance of 1, and a Gaussian machine adds its scaled luck to its mean5.

r_{t,i} = \begin{cases} 1 & \text{if } l_{t,i} \lt \mu_i(t) \\ 0 & \text{otherwise} \end{cases} \quad \text{(Bernoulli and drifting)}, \qquad r_{t,i} = \mu_i(t) + \sigma\, l_{t,i} \quad \text{(Gaussian)}
45

Here r_{t,i} is the reward machine i pays on pull t, \mu_i(t) is its mean in force at that pull, and \sigma is 0.2. For Bernoulli and drifting casinos the luck l_{t,i} is uniform on [0, 1). For Gaussian casinos it is a standard normal number. Because the table is fixed, two agents that pull the same machine on the same pull get the same reward, so the comparison is fair.

Each agent runs on its own random stream, seeded with the casino seed plus 2,000,029. Its random choices, such as epsilon-greedy's coin flip or Thompson sampling's draws, therefore never disturb the casino7.

The regret is the reward given up. At pull t, the expected loss is the gap between the best mean and the mean of the machine pulled. Over the T pulls of the game, the regret is the sum of these gaps. It is measured on the means rather than on the luck of single pulls, so it is the expected loss.

R_T = \sum_{t=0}^{T-1} \Bigl(\max_i \mu_i(t) - \mu_{a_t}(t)\Bigr)
8

Here a_t is the arm pulled on pull t, T is the horizon (the number of pulls), and the code counts pulls from 0. Regret never decreases, and it grows slowly for an agent that finds the best machine quickly.

Every agent is run by the same loop. The agent chooses, the casino pays, the regret is added, and then the agent learns from the reward. The loop is shown here with its full bookkeeping.

9 
function RUN-AGENT(agent, casino):
    cum ← 0
    for t in 0 to horizon − 1:
        arm ← agent.CHOOSE()                 # sees only past rewards
        reward ← REWARD(t, arm)
        m ← MEANS-AT(t)
        cum ← cum + max(m) − m[arm]          # expected regret of this pull
        agent.UPDATE(arm, reward)            # the reward is the only feedback
    return cum
function RUN-AGENT(agent, casino):
    arms, rewards, regret, optimal ← empty lists
    cum ← 0
    for t in 0 to horizon − 1:
        arm ← agent.CHOOSE()
        reward ← REWARD(t, arm)
        m ← MEANS-AT(t)                      # the k means in force at pull t
        cum ← cum + max(m) − m[arm]          # expected regret of this pull
        append arm to arms
        append reward to rewards
        append cum to regret
        append (m[arm] = max(m)) to optimal  # True if a best machine was pulled
        agent.UPDATE(arm, reward)            # learn after the record is kept
    return arms, rewards, regret, optimal

Example. The generator makes the best mean lead the second best by at least 0.05. A pull of a machine whose mean is 0.05 below the best mean adds 0.05 to the regret.

Greedy

Greedy pulls the machine with the best sample mean, the average reward it has paid so far. If machine i has been pulled n_i times with total reward S_i, its estimate is the average10.

\hat\mu_i = \frac{S_i}{n_i}, \qquad a_t = \arg\max_i \hat\mu_i
1011

Here \hat\mu_i is the sample mean and a_t the arm chosen on pull t. The code uses 0 as the mean of an untried machine, but this value is never compared, because of the forced round below. Ties go to the lowest index.

The first K pulls are a forced round: on pull t < K the agent pulls machine t, so every machine has one reward before any mean is compared12. Greedy never explores on purpose, so it can lock onto a machine that looked good early. On Bernoulli machines its regret at T = 10,000 is 679.9 on average, with a wide band (see the results below).

11 
function GREEDY(t, K, means):
    if t < K:
        return t                         # forced round: try each machine once
    return argmax(means)                 # the best average so far
function GREEDY-CHOOSE(t, K, counts, sums):
    if t < K:
        return t                         # forced round: machine t has no pulls yet
    for i in 0 to K − 1:
        m[i] ← sums[i] / counts[i] if counts[i] > 0 else 0
    return argmax(m)                     # the lowest index wins a tie

The full version computes the means from the counts and sums on every pull. The code also keeps them in a list for the watch mode and the page, and that bookkeeping is left out of the pseudocode.

Epsilon-greedy

Epsilon-greedy takes the greedy choice most of the time. With probability epsilon it pulls a machine chosen uniformly from all K machines, so it keeps learning about the rest. A random pull can land on the best machine too, so an exploring pull does not always lose reward. The page offers a fixed epsilon and a decaying one.

\varepsilon_t = 0.1 \quad\text{(fixed)}, \qquad \varepsilon_t = \min\bigl(1, K / t\bigr) \quad\text{(decaying)}
13

Here \varepsilon_t is the chance of an exploring pull on pull t, K is the number of machines, and t is the number of pulls made so far. The decaying schedule starts at 1 and falls as evidence accumulates, so exploration is heavy early and light later.

Each pull draws two random numbers. The first decides between explore and exploit, and the second, used only when exploring, picks the machine.

14 
function EPSILON-GREEDY(t, K, ε, means):
    if t < K:
        return t                         # forced round
    if UNIFORM() < ε:
        return INDEX(K)                  # explore: a uniform machine, 0 to K − 1
    return argmax(means)                 # exploit: the best average so far
function EPSILON-GREEDY-CHOOSE(t, K, counts, sums, decay):
    if t < K:
        return t                         # forced round
    for i in 0 to K − 1:
        m[i] ← sums[i] / counts[i] if counts[i] > 0 else 0
    if decay:
        ε ← min(1, K / t)                # epsilon fades as pulls accumulate
    else:
        ε ← 0.1
    if UNIFORM() < ε:                  # first draw: explore or exploit
        arm ← INDEX(K)                   # second draw: min(K − 1, int(UNIFORM() × K))
    else:
        arm ← argmax(m)
    return arm

The decaying variant is the same procedure with \varepsilon_t replaced by \min(1, K / t). The code computes it from t, the pulls so far. The schedule is only used after the forced round, so t \ge K whenever it is evaluated.

UCB1 (optimism)

UCB1 is an upper confidence bound rule. Each machine gets an index, its sample mean plus a bonus that is large when the machine has few pulls. Each pull picks the largest index. Under-tried machines therefore look good until they have been tested15.

\mathrm{UCB}_i(t) = \hat\mu_i + \sigma \sqrt{\frac{2 \ln t}{n_i}}, \qquad a_t = \arg\max_i \mathrm{UCB}_i(t)
16

Here t is the number of pulls made so far and n_i the number of pulls of machine i. The scale \sigma is 1 for Bernoulli and drifting machines and 0.2 for Gaussian ones, so the bonus matches the noise. The constant 2 is the one in the bound of Auer, Cesa-Bianchi and Fischer (2002).

The bonus shrinks as n_i grows, but it grows with \ln t, so a machine that is rarely pulled keeps a large bonus. Its index rises until it is tested again.

15 
function UCB1(t, K, counts, sums, σ):
    if t < K:
        return t                         # forced round
    for i in 0 to K − 1:
        index[i] ← sums[i] / counts[i] + σ × sqrt(2 × log(t) / counts[i])
    return argmax(index)                 # the largest optimistic bound
function UCB1-CHOOSE(t, K, counts, sums, σ):
    if t < K:
        return t                         # forced round: every count is at least 1 after it
    for i in 0 to K − 1:
        m[i] ← sums[i] / counts[i] if counts[i] > 0 else 0
        bonus ← σ × sqrt(2 × log(t) / counts[i])
        index[i] ← m[i] + bonus
    return argmax(index)                 # the lowest index wins a tie

log in the pseudocode is the natural logarithm, written \ln in the formulas.

Thompson sampling

Thompson sampling keeps a posterior for each machine: the belief about its mean given the rewards so far. Each pull draws one sample from every posterior and pulls the machine with the best sample. A machine that is still uncertain sometimes draws high and gets pulled, so the chance of a pull is the chance that the machine is the best under the current beliefs. This is called probability matching. As the posteriors narrow, the draws settle.

For Bernoulli machines the prior is uniform, Beta(1, 1). After S_i wins in n_i pulls, the posterior is a Beta distribution17.

\theta_i \sim \mathrm{Beta}\bigl(1 + S_i,\; 1 + n_i - S_i\bigr)
18

Here \theta_i is the sample drawn for machine i, S_i is its number of wins (the reward sum, since rewards are 0 or 1), and n_i - S_i its losses. The Beta draw is X / (X + Y) with X and Y independent gamma variates (see the box below).

Gaussian machines have a normal prior on the mean, N(0, 1), and known noise \sigma = 0.2. The posterior precision (the inverse variance) is \tau_i, the posterior mean is m_i, and the posterior standard deviation is s_i:

\tau_i = 1 + \frac{n_i}{\sigma^2}, \qquad m_i = \frac{S_i / \sigma^2}{\tau_i}, \qquad s_i = \frac{1}{\sqrt{\tau_i}}, \qquad \theta_i = m_i + s_i\, z_i
1920

Here S_i is the sum of rewards from machine i, z_i is a standard normal draw, and the code's \sigma is the Gaussian noise scale. Thompson has no forced round, so its first pulls are drawn from the prior.

function THOMPSON(K, posterior):
    for i in 0 to K − 1:
        θ[i] ← a sample from machine i's posterior
    return argmax(θ)                     # pull the best sample
function THOMPSON-CHOOSE(K, counts, sums, bernoulli, σ):
    for i in 0 to K − 1:
        if bernoulli:
            a[i] ← 1 + sums[i]
            b[i] ← 1 + counts[i] − sums[i]
        else:
            τ ← 1 + counts[i] / σ²
            a[i] ← (sums[i] / σ²) / τ    # posterior mean
            b[i] ← 1 / sqrt(τ)           # posterior standard deviation
    for i in 0 to K − 1:
        if bernoulli:
            θ[i] ← BETA-SAMPLE(a[i], b[i])
        else:
            θ[i] ← a[i] + b[i] × NORMAL-SAMPLE()
    return argmax(θ)                     # the best sample this round

function BETA-SAMPLE(α, β):
    x ← GAMMA-SAMPLE(α)
    y ← GAMMA-SAMPLE(β)
    return x / (x + y)
function GAMMA-SAMPLE(shape):          # Marsaglia and Tsang, for shape ≥ 1
    d ← shape − 1 / 3
    c ← 1 / sqrt(9 × d)
    while true:
        x ← NORMAL-SAMPLE()
        v ← 1 + c × x
        if v ≤ 0:
            continue
        v ← v × v × v
        u ← UNIFORM()
        if u ≤ 0:
            continue
        if u < 1 − 0.0331 × x × x × x × x:
            return d × v
        if log(u) < 0.5 × x × x + d × (1 − v + log(v)):
            return d × v

function NORMAL-SAMPLE():                # polar method: a point in the unit disc
    while true:
        u ← 2 × UNIFORM() − 1
        v ← 2 × UNIFORM() − 1
        s ← u × u + v × v
        if 0 < s < 1:
            break
    return u × sqrt(−2 × log(s) / s)

function BETA-SAMPLE(α, β):
    x ← GAMMA-SAMPLE(α)
    y ← GAMMA-SAMPLE(β)
    return x / (x + y)

The Beta draw needs gamma variates with shape at least 1, which is all the posteriors use: a uniform prior gives shape 1 or more. The normal draw uses the polar method, which keeps a point inside the unit disc and returns one coordinate scaled by \sqrt{-2 \ln s / s}.

EXP3 (exponential weights)

EXP3 keeps a weight w_i for each machine and pulls machines in proportion to their weights. It makes no statistical assumption about the payouts, so it suits machines that change. Its probabilities mix the weights with uniform exploration, so every machine keeps a probability of at least \gamma / K24.

p_i = (1 - \gamma)\,\frac{w_i}{\sum_j w_j} + \frac{\gamma}{K}
24

Here p_i is the probability of pulling machine i on the next pull, and \gamma is the exploration rate, the share of the probability spread uniformly over all machines. The sum is over all machines j.

\gamma = \min\left(1,\ \sqrt{\frac{K \ln K}{(e - 1)\,T}}\right)
25

This is the tuning Auer et al. give for a known horizon, so \gamma depends on the horizon T. The cap at 1 applies only for T of 4 or fewer when K = 5. Example. With K = 5 and T = 10,000, \gamma is 0.0216. With T = 300 it is 0.125.

After pull a with reward r, the estimate \hat r = r / p_a divides the reward by the probability of pulling that machine, which keeps the estimate unbiased. The weight of the pulled machine grows by a factor of \exp(\gamma \hat r / K). Then every weight is divided by the largest weight, so the weights stay at most 1. Dividing by a common constant leaves the probabilities unchanged, so the rescaling only prevents overflow26.

\hat r = \frac{r}{p_a}, \qquad w_a \leftarrow w_a\, \exp\!\Bigl(\frac{\gamma\,\hat r}{K}\Bigr), \qquad w_i \leftarrow \frac{w_i}{\max_j w_j}
27

    return a machine drawn with probability p

function EXP3-UPDATE(arm, reward, p, γ, K, w):
    estimate ← reward / p[arm]           # divided by the probability of the pull
    w[arm] ← w[arm] × exp(γ × estimate / K)
    top ← max(w)
    for i in 0 to K − 1:
        w[i] ← w[i] / top                # the largest weight becomes 1

The weights start at 1 for every machine. A machine that pays often gains weight quickly, but the uniform mix keeps the others in play. The uniform mix guarantees that each machine keeps a probability of at least \gamma / K, so no machine is starved of pulls.

Sliding-window UCB

Sliding-window UCB runs UCB1 on only the last W = 200 pulls, counted across all machines. A pull older than the window stops counting, so a machine whose payout has changed is not judged on old evidence. The counts and sums over the window are n^W_i and S^W_i, and the index is29.

\mathrm{UCB}^W_i(t) = \frac{S^W_i}{n^W_i} + \sigma \sqrt{\frac{\xi \ln \min(t, W)}{n^W_i}}
30

Here \xi is 0.6. It is smaller than UCB1's 2, because the window already limits how long evidence lasts. The value 0.6 is a fixed choice and was not tuned. A machine with no pulls in the window is tried first, in index order.

31 
function SW-UCB-CHOOSE(t, K, W, ξ, σ):
    if some machine i has no pulls in the window:
        return i                         # try it first
    for i in 0 to K − 1:
        index[i] ← window mean + σ × sqrt(ξ × log(min(t, W)) / window count)
    return argmax(index)
function SW-UCB-UPDATE(arm, reward):
    counts[arm] ← counts[arm] + 1        # all-time totals, as for every agent
    sums[arm] ← sums[arm] + reward
    t ← t + 1
    append (arm, reward) to recent       # the window, oldest first
    wcounts[arm] ← wcounts[arm] + 1
    wsums[arm] ← wsums[arm] + reward
    if length of recent > W:
        (old-arm, old-reward) ← remove the oldest entry of recent
        wcounts[old-arm] ← wcounts[old-arm] − 1
        wsums[old-arm] ← wsums[old-arm] − old-reward

function SW-UCB-CHOOSE(t, K, W, ξ, σ):
    for i in 0 to K − 1:
        if wcounts[i] = 0:
            return i                     # not in the window: try it first
    log_t ← log(min(t, W))
    for i in 0 to K − 1:
        index[i] ← wsums[i] / wcounts[i] + σ × sqrt(ξ × log_t / wcounts[i])
    return argmax(index)                 # the lowest index wins a tie

The window is what makes this agent adapt. Each pull enters the window once, and when the window is full the oldest pull leaves, which subtracts its reward from its machine's window sum. The forced check looks at the window counts, not the all-time counts, so a machine that has left the window is tried again.

The Lai-Robbins floor

For fixed machines, Lai and Robbins (1985) proved a lower bound on regret. A consistent policy, one whose regret grows more slowly than any power of T on every set of machines, must have regret at least about c \ln T, asymptotically. The constant c depends only on the means. The bound is a reference shape for comparing agents, not a guarantee at one horizon32.

c = \sum_{i:\ \mu_i < \mu^*} \frac{\mu^* - \mu_i}{\mathrm{KL}(\mu_i \,\|\, \mu^*)}, \qquad \mathrm{KL}(p \,\|\, q) = p \ln\frac{p}{q} + (1 - p) \ln\frac{1 - p}{1 - q}
3332

Here \mu^* is the best mean, and the sum runs over the machines with a smaller mean. \mathrm{KL}(p \,\|\, q) is the Kullback–Leibler divergence, the distance from a Bernoulli distribution with mean p to one with mean q, in nats. For Gaussian machines with known noise \sigma, the divergence is (\mu^* - \mu_i)^2 / (2\sigma^2), so each machine adds 2\sigma^2 / (\mu^* - \mu_i) to c.

32 
function LAI-ROBBINS-RATE(means):
    best ← max(means)
    rate ← 0
    for each p in means with p < best:
        rate ← rate + (best − p) / KL(p, best)
    return rate
function LAI-ROBBINS-RATE(means, kind, σ):
    if kind = drifting:
        raise an error: drifting machines have no single bound
    best ← max(means)
    rate ← 0
    for each p in means:
        gap ← best − p
        if gap ≤ 0:
            continue                         # the best machine adds nothing
        if kind = bernoulli:
            kl ← p × log(p / best) + (1 − p) × log((1 − p) / (1 − best))
        else:
            kl ← gap × gap / (2 × σ × σ)
        rate ← rate + gap / kl
    return rate

Averaged over the benchmark's machine sets, c = 7.342 for Bernoulli machines, which gives a floor of 67.6 at T = 10,000. For Gaussian machines c = 1.448, a floor of 13.334. The constant grows as machines get close, because close machines are hard to tell apart. For fixed casinos, the race chart draws c \ln t as a dashed line.

Example. With c = 7.342, the floor at T = 10,000 is 7.342 \times \ln 10{,}000 \approx 67.6.

The browser port

The page runs the same casino and agents in JavaScript (web/js/bandits-core.js35). The random numbers come from mulberry32, a small 32-bit generator, so the page reproduces the Python draws exactly. Python's built-in generator cannot be matched in JavaScript, which is why the project uses this one. Each 32-bit output is divided by 232 to give a uniform number in [0, 1)36.

The multiplications keep only the low 32 bits, as Math.imul does in JavaScript. The page's agents then draw their numbers in the same order as the Python code, so an agent makes the same pulls on the same seed.

The parity test checks this for 17 agent and casino pairs (the lineups of the three casino kinds) on seeds 0 to 4 over 1,200 pulls. Arms, the optimal flags and the reasons must match exactly. Rewards and regret must agree to 1e-9, because the Gaussian draws use logarithms and square roots, which can differ in the last bit between Python and JavaScript38.

When a player reveals the casino, the page scores the player's pulls on the same outcome table and posts them to the server, which computes the regret with the Python agents. The server's numbers replace the page's own table once they arrive.
