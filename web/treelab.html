HOW IT WORKS

A decision tree answers a chain of yes/no questions about the features. Each question is a split x < t that cuts the region in two; the tree keeps splitting while a split makes its pieces purer. A random forest trains many such trees on random samples and averages them. The page runs a JavaScript port of the Python trees that builds the same tree for the same seed.

Decision trees

New to this? Play twenty questions with the plane. "Is x less than 0.4?" tells you which half to look in, and the next question narrows it further. A tree is a whole list of these questions, arranged so that each answer leads to the next. The last question in each branch gives a class.

Each internal node stores a feature and a threshold. A point goes left when feature < threshold, right otherwise. Each leaf predicts the majority class of the training rows that reach it, and its confidence is that majority's share.

Gini vs entropy

New to this? Impurity measures how mixed a group is. A group of only one class scores zero. A 50/50 group scores the worst. Both measures agree on the extremes; they differ only in the middle.

Gini impurity is 1 − Σp², the chance that two random rows from a node disagree on the class if you labelled one at random by the node's mix. Entropy is −Σp log₂p, the average surprise in bits. Gini needs no logarithm, so it is faster; entropy punishes mixed nodes a little more. A split is scored by how much it lowers the size-weighted impurity of its two children.

Greedy splitting and the search

New to this? Greedy means: take the best question right now and never reconsider it. It is not always the best tree overall, but finding the best tree exactly is hopeless, and the greedy choice works well in practice.

At a node, sort its rows on each feature. Test the midpoint between every pair of neighbouring values, count the classes on each side, and keep the threshold with the largest gain. Growth is breadth-first: each step splits the next node in the queue. A node stops when it is pure, has reached the depth limit, or would leave a child with fewer than the minimum samples per leaf.

Overfitting and pruning

New to this? A tree can keep asking questions until every point has its own box. That memorises the training rows, including their noise. A test set, rows the tree never saw, shows when that stops helping.

Cost-complexity pruning scores each internal node by how much error it saves per extra leaf: g(t) = (R(t) − R(subtree)) / (leaves − 1), where R is the misclassification rate. The weakest link is collapsed first, and α sets the price of a leaf. The sequence of trees shrinks monotonically as α rises. Depth and minimum leaf size are the simpler brakes; the chart shows the depth at which test accuracy peaks.

Bagging and random forests

New to this? One tree is unstable: move a few points and its questions change. Train many trees on slightly different data and average their votes, and the random wobbles cancel out.

Bagging draws n rows with replacement for each tree, so about 37% of rows are left out of each sample. Those out-of-bag rows score the tree without a separate test set. A random forest adds one more source of variety: at each split only a random subset of features, usually √p, is considered. The averaged class probabilities form the glowing forest boundary; the faint jagged lines are the individual trees.

Parameters, defaults and why

ParameterDefaultWhy
ImpurityGiniSame ranking as entropy in most cases, and no logarithm: cheaper for every candidate threshold. Switch to entropy to see the difference in the middle.
Max depth5Deep enough to show the structure of blobs and XOR, shallow enough that the diagram stays readable. The accuracy-vs-depth chart shows where going deeper stops helping.
Min samples per leaf3A leaf of one or two points is a single noisy row. Three keeps each region backed by a few neighbours without blocking the clean splits.
Test share0.3A common split: enough held-out rows to see the train/test gap, while most of the data still trains the model.
Extra featuresOnx·y and x²+y² let an axis-aligned tree draw curved boundaries. Without them, XOR and rings need many small steps. The forest tries √4 = 2 of the 4 features per split.
Prune α0No pruning until asked. Pruning is a view: the full tree stays grown underneath.
Trees25Enough votes that the averaged boundary is smooth and the out-of-bag estimate settles; the slider goes to 100 to compare.
Bootstrap rowsOnBootstrapping gives each tree a different sample and supplies the out-of-bag estimate. Off means every tree sees the same rows, so the forest differs only by feature subsets.

Reading the numbers: Train accuracy only goes up as the tree deepens. Test accuracy rises, peaks, and falls. The forest's out-of-bag accuracy is a free estimate of its test accuracy. Noisy diagonal labels are flipped 15% of the time, so no model can exceed about 85%; a single deep tree usually scores below a forest there because it fits the flipped rows.
