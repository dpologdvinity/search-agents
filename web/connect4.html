HOW IT WORKS

The AlphaZero agent is a neural network that learned to play by playing itself, combined with a tree search that uses the network to choose moves. Two classic baselines sit beside it: minimax with alpha-beta pruning, which looks a fixed number of moves ahead with a hand-written score, and Monte Carlo tree search, which judges positions by random games.

AlphaZero (PUCT search with a network)

New to this? A chess player looks at a few candidate moves, pictures how each might go, and trusts a sense of who is winning. Here the network supplies the sense and the search does the picturing. Each game it plays against itself sharpens both.

PUCT tree search. At each node it picks the move that maximises Q + U, where U = c_puct · P · √(N+1) / (1 + N(move)), P is the network's prior for the move, and N counts visits. The move played is the most visited one.

  • c_puct = 2.0
  • 50, 200 or 800 simulations per move at Fast, Normal and Strong

Minimax with alpha-beta pruning

New to this? Plan a few moves ahead, assume each side picks its best reply, and score the position at the end. Alpha-beta skips branches that cannot change the final choice, so the same look-ahead costs less.

Negamax with alpha-beta pruning, a transposition table, and iterative deepening: each depth finishes before the next starts, and an unfinished depth is thrown away. Columns are tried centre-first (3, 2, 4, 1, 5, 0, 6), so good moves prune more.

  • Time budget 0.1 s, 0.5 s or 2.0 s at Fast, Normal and Strong; maximum depth 42

Monte Carlo tree search (MCTS)

New to this? To judge a position, play many random games from it and count how often you win. Each round spends more effort on moves that have looked good so far, and less on the rest.

UCT tree search with random rollouts to the end of the game and no neural network. The move chosen is the child visited most often.

  • UCB1 exploration constant c = 1.4
  • 300, 1,500 or 5,000 simulations, capped at 3 seconds

How these were chosen: hand-set. The numbers are fixed in connect4/minimax.py and no tuning run is recorded. The code describes the evaluation as a standard hand-built one but cites no source. The MCTS constant and the PUCT constant were also set by hand; no sweep is recorded.

Training

The network learns from self-play only: no human games, no opening book, and no positions labelled by another engine. The architecture is a residual network with 4 blocks of 32 channels, a policy head that scores the 7 columns, and a value head that predicts the result from the side to move. Each iteration plays 128 games at once and trains on a replay buffer with mirrored positions. The loss is value mean squared error plus policy cross-entropy against the search's visit counts. During self-play, the root gets Dirichlet noise (alpha 1.0, weight 0.25), and the first 8 moves of each game are sampled from the visit counts.

The training doc gives the run as 64 simulations per move and 100 training steps per iteration (the training script's current defaults are 100 and 400). On one shared laptop CPU (Intel Core i7-1265U, no GPU), it played 4,480 games over 35 iterations, about 2 hours 40 minutes of compute. The weights served on this page are the snapshot after iteration 19 (2,432 games), before the later phases. Against alpha-beta minimax at depths 2, 4 and 6 (50 games each, 200 simulations per move), that snapshot scored 64%, 77% and 44%. Plain MCTS with 1,000 simulations scored 32 wins, 2 draws, 16 losses against depth 4. The full run is in docs/connect4-training.md.
