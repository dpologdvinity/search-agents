HOW IT WORKS

The AlphaZero agent is a neural network that learned to play by playing itself, combined with a tree search that uses the network to choose moves. Two classic baselines sit beside it: minimax with alpha-beta pruning, which looks a fixed number of moves ahead with a hand-written score, and Monte Carlo tree search, which judges positions by random games. A chance player sits at the bottom of the scale: it rolls for its column with fixed odds and never looks at the position.

AlphaZero (PUCT search with a network)

New to this? A chess player looks at a few candidate moves, pictures how each might go, and trusts a sense of who is winning. Here the network supplies the sense and the search does the picturing. Each game it plays against itself sharpens both.

PUCT tree search. At each node it picks the move that maximises Q + U, where U = c_puct · P · √(N+1) / (1 + N(move)), P is the network's prior for the move, and N counts visits. The move played is the most visited one.

  • c_puct = 2.0
  • 50, 200 or 800 simulations per move at Fast, Normal and Strong

Minimax with alpha-beta pruning

New to this? Plan a few moves ahead, assume each side picks its best reply, and score the position at the end. Alpha-beta skips branches that cannot change the final choice, so the same look-ahead costs less.

Negamax with alpha-beta pruning, a transposition table, and iterative deepening: each depth finishes before the next starts, and an unfinished depth is thrown away. Columns are tried centre-first (3, 2, 4, 1, 5, 0, 6), so good moves prune more.

  • Time budget 0.1 s, 0.5 s or 2.0 s at Fast, Normal and Strong; maximum depth 42

Monte Carlo tree search (MCTS)

New to this? To judge a position, play many random games from it and count how often you win. Each round spends more effort on moves that have looked good so far, and less on the rest.

UCT tree search with random rollouts to the end of the game and no neural network. The move chosen is the child visited most often.

  • UCB1 exploration constant c = 1.4
  • 300, 1,500 or 5,000 simulations, capped at 3 seconds

Chance (fixed odds)

New to this? Like the tile spawner in 2048: no thinking, just a weighted die roll over the moves that are legal.

No search, evaluation or lookahead. Each column has a fixed weight of 1, 2, 3, 4, 3, 2, 1 from the left, so the centre columns come up more often. The weights are renormalised over the columns that are not full, and the move is one draw from that distribution.

  • Odds on an empty board: 6% / 12% / 19% / 25% / 19% / 12% / 6%
  • Strength has no effect: the same odds at Fast, Normal and Strong

Heuristics and their values

HeuristicWhat it measuresValue / weight
WinA four in a row for the side to move, or against it.1,000,000 minus the ply, so faster wins score higher
Open windowsEach of the 69 four-cell lines that holds stones of only one player scores for that player: 1 stone, 2 stones, 3 stones.1, 8 and 64 points (4 stones is a win, scored separately)
Centre columnStones in the middle column, for each side.+3 per own stone, −3 per opponent stone

How these were chosen: hand-set. The numbers are fixed in connect4/minimax.py and no tuning run is recorded. The code describes the evaluation as a standard hand-built one but cites no source. The MCTS constant and the PUCT constant were also set by hand; no sweep is recorded.

Training

The network learns from self-play only: no human games, no opening book, and no positions labelled by another engine. The architecture is a residual network with 4 blocks of 32 channels, a policy head that scores the 7 columns, and a value head that predicts the result from the side to move. Each laptop iteration played 128 games at once and trains on a replay buffer with mirrored positions. The loss is value mean squared error plus policy cross-entropy against the search's visit counts. During self-play, the root gets Dirichlet noise (alpha 1.0, weight 0.25), and the first 8 moves of each game are sampled from the visit counts.

The laptop runs used 64 simulations per move and 100 training steps per iteration (--simulations 64 --steps 100; the script's defaults are 100 and 400). On one shared laptop CPU (Intel Core i7-1265U, no GPU), the first 37 iterations produced 4,736 self-play games. A Kaggle notebook then continued from that checkpoint for 8 hours on 4 CPU threads, with 512 games, 100 simulations and 400 training steps per iteration, reaching iteration 96 and 34,944 games. The weights served on this page are that iteration-96 export. Against alpha-beta minimax at depths 2, 4 and 6 (100 games each, 200 simulations per move), it scored 71%, 81% and 81%; the iteration-19 network served before it scored 63.5%, 58% and 39% on the same openings. Plain MCTS with 1,000 simulations scored 32 wins, 2 draws, 16 losses against depth 4 (50 games). The full run is in docs/connect4-training.md.
