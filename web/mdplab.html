HOW IT WORKS

The grid is a Markov decision process: a set of cells, four moves, a chance that each move slips sideways, and a reward on each step. Two solvers compute the best behaviour from the full model, and Q-learning finds it from experience alone. All three run here in JavaScript, and a Python package (python -m mdplab) reproduces the same numbers for the same seed.

The MDP

New to this? Think of a robot on a tiled floor. Each turn it picks a direction, but the floor is slippery, so it sometimes goes sideways. Some tiles pay, some cost, and every turn costs a little. The task is to choose moves that earn the most over time.

An MDP is a tuple (S, A, P, R, γ). The states S are the cells the agent can stand on. The actions A are up, right, down and left. The transition P(s′ | s, a) is 1 − slip for the intended direction and slip / 2 for each perpendicular one; a move into a wall stays put. The reward R pays the living reward on every step, plus the payout of any + or − cell entered. A + or − cell ends the episode, and a C cell (the cliff) sends the agent back to the start.

The Bellman equation

New to this? The value of a cell is the best you can expect from it: the reward of the next step plus the value of wherever you land, discounted a little. Q(s, a) is the same idea for one particular first move.

Q(s, a) = Σs′ P(s′ | s, a) · [ R(s, a, s′) + γ · V(s′) ] and V(s) = maxa Q(s, a). A terminal cell has value 0, because nothing follows it. The optimal values are the unique solution of these equations, and the greedy policy (take the best action in every cell) is optimal.

Value iteration

New to this? Start with every cell at zero. Then repeatedly update every cell from its neighbours. Each round carries information one step further from the rewards, so the values spread out like heat.

Sweep k sets Vk+1(s) = maxa Q(s, a) using Vk. The Bellman residual is maxs |Vk+1(s) − Vk(s)|. The update is a contraction: with discount γ the residual shrinks by at least a factor γ per sweep, so the stopping rule is a guarantee, not a guess. The policy is read off the final values.

Policy iteration

New to this? Alternate two questions. First, if I follow this policy, what do I get? Second, given those values, where would I do better? Repeat until neither answer changes.

Evaluation solves Vπ for the current policy by sweeps of the same backup with a fixed action per cell. Improvement sets π(s) to the best action under Vπ, keeping the current action unless the new one is better by more than 10-9. The policy only improves, and there are finitely many policies, so it stops, and when no action changes the policy is optimal. Each round costs many evaluation sweeps but few improvements, which is why it often takes fewer rounds than value iteration takes sweeps.

Q-learning and SARSA

New to this? The agent does not know the slips or the rewards in advance. It walks the grid, sometimes at random, and after each step nudges its estimate of "this move from this cell is worth this much" toward what it just saw. Over many walks the estimates settle.

After each step from s with action a, landing on s′ with reward r, the table moves by α · (target − Q(s, a)), where the target is r + γ · maxa′ Q(s′, a′) for Q-learning, and r + γ · Q(s′, a′) for SARSA, with a′ the action actually chosen next. A terminal s′ uses target = r. Actions are chosen ε-greedily: random with probability ε, otherwise the best Q, with ties broken at random. The learned greedy policy is the argmax of Q, and it is compared here with the exact optimal policy from value iteration.

Parameters and their values

ParameterDefaultWhy this value
Discount γ0.95 (cliff: 0.99)Looks about 20 steps ahead in a 11-by-11 grid, so the goal in a far corner still matters. Sutton and Barto use 1 on the cliff; with 1, a deterministic starting policy can loop forever and policy iteration never settles, so the cliff uses 0.99.
Slip p0.1 (windy: 0.3; cliff: 0)Enough that the agent must plan around the pits, not walk straight through them. The slider stops at 0.5, where the intended move is still at least as likely as either slip.
Living reward−0.04 (cliff: −1)A small cost per step, so the agent prefers a shorter route to the same goal. The cliff uses the textbook −1.
Reward + and pit −+1 and −1The goal is worth more than the cost of walking to it, and a pit is as bad as a goal is good. The cliff's −100 is the textbook fall penalty.
Step size α0.1 (cliff: 0.5)Slips make each step's target noisy. With 0.5 the table jitters and the greedy policy flips between near-equal actions; 0.1 settles. The cliff keeps the textbook 0.5, which is fine when the world is deterministic.
Exploration ε0.1, decaying to 0.01Enough random moves to find the far goal and the pits. The cliff keeps ε = 0.1 constant, so SARSA's cautious route is a real consequence of exploration.
Decay per episode0.999 (cliff: 1, constant)Explore hard early and exploit later: from 0.1 at 0.999 the rate reaches its floor of 0.01 after about 2300 episodes. The cliff keeps ε fixed for the textbook comparison.
Convergence ε (planners)1e-4 (choose 1e-2 to 1e-6)Stop when no value changes by more than this. The values are then within about ε · γ / (1 − γ) of the optimum (about 0.002 at γ = 0.95 and ε = 1e-4), and the greedy policy is usually exact well before that.
Tie tolerance1e-9Two actions within 1e-9 count as tied, so rounding noise cannot flip a policy. The Python and JavaScript versions use the same value.
Random seed1Fixes the random starting policy and every episode. The same seed gives the same walks in the browser and in python -m mdplab.

How these were chosen: The grid layouts, the rewards and the slip values were set by hand so each lesson shows: a shortcut through a pit, a corridor where the wind matters, a cliff with a textbook penalty. The discount, the step size and the exploration schedule are standard starting points, not tuned against a benchmark. The cliff's settings follow Sutton and Barto (2018, example 6.6), except for the discount, which is 0.99 for the reason given above. No parameter sweep is committed.
