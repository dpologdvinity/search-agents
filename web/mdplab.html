HOW IT WORKS

The grid is a Markov decision process (MDP): a set of cells, four moves, a chance that each move slips sideways, and a reward on each step. Two solvers compute the best behaviour from the full model, and Q-learning finds it from experience alone. All three run in JavaScript1, and the Python package python -m mdplab reproduces the same numbers for the same seed2.

The MDP

An MDP is a tuple (S, A, P, R, \gamma). The states S are the cells the agent can stand on. The actions A are up, right, down and left. A wall is not a state. A reward cell (+) and a pit (−) are terminal: entering one ends the episode. A cliff (C) is not a state either. Entering it pays the cliff value and sends the agent back to the start34.

54
P(s' \mid s, a) = \begin{cases} 1 - p & s' = \text{move}(s, a) \\ p/2 & s' = \text{move}(s, a \pm 1) \end{cases}, \qquad R(s, a, s') = r_{\text{living}} + r_{\text{entered}}(s')

Here p is the slip chance, the directions a \pm 1 are the two sideways moves (left and right of the intended one), and \text{move}(s, d) is the cell reached by moving in direction d. If that move would leave the grid or enter a wall, the result is s itself. r_{\text{living}} is the living reward paid on every step, and r_{\text{entered}}(s') is the payout of the cell entered, which is 0 on empty cells. Outcomes with probability 0 are dropped.

Bellman equations

The value V(s) is the expected discounted return from s under the best behaviour, and Q(s, a) is the value of taking action a first and acting best afterwards. The discount \gamma weights a reward one step later by \gamma, and two steps later by \gamma^2. The Bellman optimality equations relate the two. A terminal cell has value 0, because nothing follows it6.

78
Q(s, a) = \sum_{s'} P(s' \mid s, a)\,\bigl[R(s, a, s') + \gamma\, V(s')\bigr], \qquad V(s) = \max_{a} Q(s, a)

Here \sum_{s'} runs over the outcomes of the action, and V(s') is taken as 0 when s' is terminal. The greedy policy takes the action with the highest Q in each state. When two actions are within 10^{-9} of each other, the lower-index action is taken, so rounding noise cannot change the policy9. Because the optimal values are the unique solution of these equations, the greedy policy from them is optimal.

Value iteration

Value iteration starts with every value at 0 and repeats the Bellman update over every state. One sweep computes every new value from the old ones, so the update is synchronous. The Bellman residual is the largest change in any value during the sweep. The loop stops when it falls below the threshold \varepsilon10.

11
V_{k+1}(s) = \max_{a} Q_k(s, a), \qquad \delta_k = \max_{s} \bigl|V_{k+1}(s) - V_k(s)\bigr|, \qquad \text{stop when } \delta_k < \varepsilon

Here Q_k is computed from V_k with the formula above. The update is a contraction: each sweep shrinks the distance to the optimal values by at least a factor of \gamma. So when the residual is below \varepsilon, the values are within about \varepsilon\gamma / (1 - \gamma) of the optimum. At the defaults (\gamma = 0.95, \varepsilon = 10^{-4}) that bound is about 0.002.

1213 
function VALUE-ITERATION(mdp, ε):
    V(s) ← 0 for every state s
    while true:
        new ← the best Q(s, a) over the actions, from the current V, for each state s
        residual ← the largest change |new(s) − V(s)| over all states
        V ← new
        if residual < ε: stop
    return the greedy policy of V
constants: TIE = 1e−9, MAX-SWEEPS = 100000

function VALUE-ITERATION(mdp, ε):
    V(s) ← 0 for every state s;  sweeps ← 0;  residual ← infinity
    while residual ≥ ε and sweeps < MAX-SWEEPS:
        old ← a copy of V                               # synchronous: every update reads old
        residual ← 0
        for each state s:
            qs ← [ sum over (p, s', r) in P(s, a) of p · (r + γ · old(s')) , for each action a ]
            best ← max(qs)
            residual ← max(residual, |best − old(s)|)
            V(s) ← best
        sweeps ← sweeps + 1
    for each state s:
        π(s) ← the lowest-index action a with Q(s, a) ≥ max over a′ of Q(s, a′) − TIE
    return sweeps, V, π

Ideas in the full version. Each sweep reads the old values and writes new ones, so the order of the states does not matter. Terminal cells keep value 0 because they are not states. The residual is the quantity the stopping rule and the chart use. The final policy is read off the converged values, with the same tie rule as every other greedy choice.

Policy iteration

Policy iteration alternates two phases. Evaluation computes the values V^\pi of the current policy \pi, by sweeps of the Bellman update with the action fixed to \pi(s). Improvement sets each state's action to the best one under V^\pi. A state keeps its current action unless another action is better by more than 10^{-9}14.

1516
V^\pi(s) \leftarrow \sum_{s'} P(s' \mid s, \pi(s))\,\bigl[R(s, \pi(s), s') + \gamma\, V^\pi(s')\bigr], \qquad \pi(s) \leftarrow \arg\max_{a}\, Q^\pi(s, a) \ \text{unless } Q^\pi(s, \pi(s)) \ge \max_a Q^\pi(s, a) - 10^{-9}

Here Q^\pi(s, a) is the one-step look-ahead of the formula in the Bellman section, computed from V^\pi. Evaluation stops when its residual is below the threshold \varepsilon, and the page caps it at 5000 sweeps per round. The policy only improves from round to round, and a round with no changes means the policy is optimal, so the loop stops. Each round starts from the values of the previous one, so the evaluation is warm-started.

1417 
function POLICY-ITERATION(mdp, ε):
    π ← a seeded random action for every state;  V ← 0
    while the policy is not stable:
        evaluate π: sweep the Bellman update with action π(s) until the residual is below ε
        improve: for each state s, switch π(s) to the best action unless the current one is tied
        stable ← no action changed
    return π, V
constants: TIE = 1e−9, MAX-ROUNDS = 500, MAX-EVAL-SWEEPS = 5000

function POLICY-ITERATION(mdp, ε, seed):
    V(s) ← 0 for every state s;  rng ← MULBERRY32(seed)
    π(s) ← rng.index(4) for every state s                # seeded random start
    rounds ← 0;  stable ← false
    while not stable and rounds < MAX-ROUNDS:
        residual ← infinity;  used ← 0
        while residual ≥ ε and used < MAX-EVAL-SWEEPS:   # evaluation
            old ← a copy of V
            residual ← 0
            for each state s:
                q ← sum over (p, s', r) in P(s, π(s)) of p · (r + γ · old(s'))
                residual ← max(residual, |q − old(s)|)
                V(s) ← q
            used ← used + 1
        changed ← 0                                      # improvement
        for each state s:
            qs ← [ Q(s, a) computed from V, for each action a ]
            if qs[π(s)] ≥ max(qs) − TIE: continue       # keep the current action
            π(s) ← the lowest-index action a with qs[a] ≥ max(qs) − TIE
            changed ← changed + 1
        rounds ← rounds + 1
        stable ← (changed = 0)
    return π, V, rounds

Ideas in the full version. The random starting policy comes from the seed, so the same seed replays the same run. The keep-the-current-action rule means a round changes a state only when there is a real improvement, which is what makes the loop stop. The evaluation is an ordinary sweep, so it converges at the rate the discount sets. The number of rounds and evaluation sweeps are the two counts the page shows.

Q-learning and SARSA

Q-learning learns the table Q(s, a) from single steps, without the model. After each step from s with action a, which lands on s' with reward r, the entry moves toward a target. The target uses the best next action, which makes Q-learning off-policy: it learns the greedy policy whatever the agent actually does. SARSA uses the action it will actually take next, which makes it on-policy18.

19
Q(s, a) \leftarrow Q(s, a) + \alpha\,\bigl(\text{target} - Q(s, a)\bigr), \qquad \text{target} = \begin{cases} r & s' \text{ terminal} \\ r + \gamma \max_{a'} Q(s', a') & \text{Q-learning} \\ r + \gamma\, Q(s', a') & \text{SARSA, with } a' \text{ the action taken} \end{cases}

Here \alpha is the step size, r is the living reward plus the payout entered, and \gamma is the discount. The agent chooses actions epsilon-greedily: with probability \epsilon it takes a random action, and otherwise the action with the highest Q, breaking ties at random20. After each episode, \epsilon \leftarrow \max(\epsilon_{\min}, \epsilon \cdot \text{decay})21. A slip is drawn from the same random stream, so the walks depend on the seed only.

1822 
function Q-EPISODE(mdp, Q, algorithm, ε):
    s ← start;  a ← CHOOSE(s)
    loop:
        s' ← the cell reached when a slips
        r ← living reward + payout of the cell entered
        if s' is terminal: target ← r
        else if Q-learning: target ← r + γ · max over a′ of Q(s', a′)
        else: a' ← CHOOSE(s');  target ← r + γ · Q(s', a')          # SARSA
        Q(s, a) ← Q(s, a) + α · (target − Q(s, a))
        if s' is terminal or the step limit is reached: stop
        s ← s';  a ← the next action
    ε ← max(ε_min, ε · decay)
constants: TIE = 1e−9, MAX-STEPS = 500

function CHOOSE(s):
    if uniform() < ε: return index(4)           # explore: a random action
    top ← max of Q(s, a) over the four actions
    ties ← the actions with Q(s, a) ≥ top − TIE, in index order
    if there is one tie: return it
    return ties[index(number of ties)]              # random tie-break

function Q-EPISODE(mdp, Q, algorithm, ε, α, γ):
    s ← start;  a ← CHOOSE(s);  ret ← 0;  steps ← 0
    loop:
        d ← DIRECTION(a, uniform())                  # the direction actually moved (slip)
        (s', pay) ← RESULT(s, d)                     # wall: stay; cliff: pay, go to start
        r ← living + pay
        ret ← ret + r;  steps ← steps + 1
        if s' is terminal: target ← r; a' ← none
        else if algorithm = SARSA:
            a' ← CHOOSE(s');  target ← r + γ · Q(s', a')
        else:
            target ← r + γ · max of Q(s', ·)
        Q(s, a) ← Q(s, a) + α · (target − Q(s, a))
        if s' is terminal or steps ≥ MAX-STEPS: stop
        s ← s';  a ← a' if SARSA else CHOOSE(s')
    ε ← max(ε_min, ε · decay)
    return ret, steps

Ideas in the full version. The random draws happen in a fixed order: the exploration test and index, then the slip draw, then the tie-break index. Fixing that order is what lets the browser and the Python package produce identical walks. The step limit ends an episode that never reaches a terminal cell, and that episode is not counted as falling. In SARSA the next action is chosen before the update, because its value is part of the target, and the same action is then taken on the next step.

Example. On the cliff walk with the textbook settings (α = 0.5, ε = 0.1 held constant, γ = 0.99, seed 1), 500 episodes of Q-learning leave a greedy route of 13 steps along the row beside the cliff. That route is optimal. After the same 500 episodes, SARSA's greedy route takes 17 steps and runs two rows further from the cliff. The test suite checks the same contrast in online return, where SARSA earns more during learning23.
