HOW IT WORKS

The solver is a search over pushes. Walking costs nothing in the search, so each step of the search is one push. The search stops at the first position where every box sits on a goal. Three priority rules (A*, greedy best-first and breadth-first search) share one loop. Two lower bounds on the pushes still needed, and two deadlock tests, keep the loop away from positions that cannot be finished.

States and pushes

A state is what the search remembers about a position. The player's exact square matters only through the region it can walk to, because every square in that region can start the same pushes. So a state keeps the smallest square of the player's region and the sorted list of box squares. The walk region R(p, B) is the set of floor squares the player can reach from p without crossing a box.

s = \bigl(\min R(p, B),\ B\bigr)
1

Here p is the player's square, B is the set of box squares, and \min R(p, B) is the smallest square in the walk region. The first state is built from the level's start. Each successor is made by a push: for each square p in the walk region and each direction, if a box sits on the next square b and the square beyond it is open and empty, the box moves there. The player then stands on b. Each push costs one unit, so the depth of the search is the number of pushes.

A* search

A\* is a best-first search that always expands the state with the smallest priority f = g + h. Here g is the number of pushes from the start to the state, and h is a heuristic, an estimate of the pushes still needed. A heuristic is admissible when it never exceeds the pushes really left. With an admissible heuristic, the first goal state taken from the queue has the fewest pushes.

The page starts with A* using the matching bound and deadlock pruning on. HINT and SOLVE use the selected algorithm and heuristic from the side panel. COMPARE runs the same search twice, once with pruning off and once with it on.

\text{priority}(g, h) = \begin{cases} (g,\ 0) & \text{BFS} \\ (h,\ g) & \text{greedy} \\ (g + h,\ h) & \text{A*} \end{cases}
2

The priority is a pair. The first number is compared first, and the second breaks ties. For A*, the tie goes to the state with the smaller h, which is the state closer to the goal by the estimate.

3 
function SEARCH(level, rule):                   # rule is BFS, GREEDY or A*
    OPEN ← {start state};  best-g[start] ← 0
    while OPEN is not empty:
        s ← the state in OPEN with the smallest priority
        remove s from OPEN
        if every box of s is on a goal:
            return PLAN(s)
        for each push t from s:                  # walking between pushes is free
            if t is a deadlock:
                continue                         # pruned before it is stored
            if g(s) + 1 < best-g[t]:
                best-g[t] ← g(s) + 1
                add t to OPEN
    return no solution
constants: DEFAULT-NODES = 20,000, DEFAULT-SECONDS = 10

function SEARCH(level, algorithm, heuristic, prune, budget, time-limit):
    if algorithm = BFS:
        heuristic ← none                         # BFS has no heuristic
    if prune and IS-DEADLOCK(start boxes):
        return status exhausted                  # no push can help
    start ← (MIN-REACHABLE(start player, start boxes), sorted start boxes)
    best-g[start] ← 0;  info[start] ← (none, start player, −1, −1)
    h-cache ← empty                              # h depends only on the boxes
    CLOSED ← empty set
    counter ← 0                                  # breaks ties between equal entries
    OPEN ← heap holding (PRIORITY(0, h(start)), counter, start, 0)
    expanded ← 0;  generated ← 0;  pruned ← 0
    while OPEN is not empty:
        (key, g) ← the entry in OPEN with the smallest priority; remove it
        if key is in CLOSED or g > best-g[key]:    # stale entry: expanded already, or a cheaper path came later
            continue
        boxes ← the box squares of key
        if boxes = goals:                        # every box is on a goal
            return status solved, PLAN(key)
        if expanded ≥ budget:
            return status budget
        if the time since the start > time-limit:
            return status time
        add key to CLOSED;  expanded ← expanded + 1
        for each square p in WALK-REGION(player square in info[key], boxes):
            for each direction d in (up, down, left, right):
                b ← p + d                        # the square of the box to push
                if no box is on b:
                    continue
                nb ← b + d                       # where the box lands
                if nb is a wall or holds a box:
                    continue
                generated ← generated + 1
                new-boxes ← (boxes − {b}) ∪ {nb}
                if prune and IS-DEADLOCK(new-boxes):
                    pruned ← pruned + 1
                    continue
                ckey ← (MIN-REACHABLE(b, new-boxes), new-boxes)   # the player now stands on b
                if g + 1 ≥ best-g[ckey]:         # best-g of an unseen key is infinity
                    continue
                best-g[ckey] ← g + 1
                remove ckey from CLOSED          # reopen: a cheaper path was found
                info[ckey] ← (key, b, b, d)      # parent, player square, box square before the push, direction
                if new-boxes is not in h-cache:
                    h-cache[new-boxes] ← h(new-boxes)
                counter ← counter + 1
                push (PRIORITY(g + 1, h-cache[new-boxes]), counter, ckey, g + 1) onto OPEN
    return status exhausted

function PLAN(final-key):
    chain ← the keys from the start to final-key, by following the parent links in info
    player ← start player;  boxes ← start boxes;  moves ← empty
    for each key in chain:
        (parent, cell, b, d) ← info[key]
        push-cell ← b − d                        # the player stands behind the box
        walk ← WALK-PATH(player, push-cell, boxes)   # breadth-first, around the boxes
        if walk does not exist:
            raise error "the planned push cell is unreachable"
        append walk, then the push letter in capitals, to moves
        boxes ← (boxes − {b}) ∪ {b + d};  player ← b
    return moves

Lazy deletion. The open list is a heap, and a state that gets a cheaper path is pushed again rather than moved in place. The older entry stays in the heap with a larger g, and the stale check skips it when it reaches the top.

Reopening. When a cheaper path reaches a state that was already expanded, the state leaves the closed set and is expanded again. With a consistent heuristic this never happens. The matching bound's Manhattan fallback can break consistency, so reopening keeps A* optimal for any admissible heuristic.

Plan replay. Each state stores its parent, the player's square, and the box that was pushed. PLAN walks the chain from the start and replays each push, so the plan is a move string that the page and the terminal can replay.

Budgets. The node budget counts expansions, and the time limit is checked once for each state taken from the queue. The run also records a progress sample every \max\bigl(1, \lfloor \text{budget} / 200 \rfloor\bigr) expansions, and the COMPARE counters replay those samples.

Greedy best-first search

Greedy best-first search uses the same loop with the priority (h, g): it always expands the state that looks closest to the goal by the heuristic, and g only breaks ties. The loop expands few states, but a state that looks close can lead to a dead end, so the plan it returns can be longer than the shortest one. The benchmark pairs it with the matching bound.

  • It solves all 12 levels with pruning on and off, and 11 of the 12 plans are optimal in both runs.
  • On the Aisle level it returns a 20-push plan where the optimum is 18.

Breadth-first search

Breadth-first search uses the same loop with the priority g alone. It has no heuristic, so h = 0. Every push costs one unit, so the first goal state taken from the queue has the fewest pushes, but it never looks toward the goal. It is the baseline for the node counts.

  • With a 20,000-node budget it solves 8 of 12 levels with pruning off and 10 of 12 with pruning on.

Matching bound (Hungarian algorithm)

Each box must end on its own goal, so the pushes still needed are at least the cost of the cheapest one-to-one pairing of boxes and goals. The cost c(b, g) of pairing box b with goal g is the push distance from b to g, defined below. When no push path joins them, the cost is the Manhattan distance, the number of rows plus columns between the two squares. The matching bound is the minimum total cost over all pairings.

h_{\text{match}}(B) = \min_{\sigma} \sum_{b \in B} c\bigl(b,\ \sigma(b)\bigr)
4

Here \sigma ranges over every one-to-one pairing of the boxes in B with the goals G, and \sigma(b) is the goal paired with box b. The number of boxes equals the number of goals, so each pairing covers every goal once. The minimum over pairings is computed by the Hungarian algorithm, an exact method for this minimum-cost matching problem that runs in O(n³) time for n boxes. It keeps dual potentials for the rows and columns, which keep every reduced cost non-negative, and it grows an alternating tree from one unmatched row at a time until it finds a free column.

45 
function MATCHING-BOUND(boxes):
    cost ← the cost of pairing each box with each goal    # push distance, or Manhattan fallback
    total ← MIN-COST-MATCHING(cost)                       # cheapest one-to-one pairing
    return total
function MIN-COST-MATCHING(cost):              # rows and columns are numbered from 1 here
    n ← the number of rows
    u, v ← n + 1 zeros                            # potentials for rows and columns
    p, way ← n + 1 zeros                          # p[j]: the row matched to column j, 0 for none
    for i from 1 to n:
        p[0] ← i;  j0 ← 0
        minv ← n + 1 copies of infinity           # cheapest reduced cost from the tree to each column
        used ← n + 1 copies of false
        while True:
            used[j0] ← true
            i0 ← p[j0]
            delta ← infinity;  j1 ← 0
            for j from 1 to n:
                if not used[j]:
                    cur ← cost[i0][j] − u[i0] − v[j]     # reduced cost, never negative (the code indexes cost from 0)
                    if cur < minv[j]:
                        minv[j] ← cur;  way[j] ← j0
                    if minv[j] < delta:
                        delta ← minv[j];  j1 ← j
            for j from 0 to n:
                if used[j]:
                    u[p[j]] ← u[p[j]] + delta;  v[j] ← v[j] − delta
                else:
                    minv[j] ← minv[j] − delta
            j0 ← j1
            if p[j0] = 0:                         # a free column: the tree has reached one
                break
        while True:                               # flip the augmenting path back to the root
            j1 ← way[j0]
            p[j0] ← p[j1]
            j0 ← j1
            if j0 = 0:
                break
    match ← n zeros
    for j from 1 to n:
        match[p[j] − 1] ← j − 1
    total ← sum of cost[r][match[r]] over every row r
    return total, match

Potentials. The vectors u (rows) and v (columns) are dual potentials. The reduced cost \text{cost} - u - v is never negative, and it is zero on the edges the tree has made tight. Each step finds the smallest reduced cost \delta to an unused column and shifts the potentials by it, which makes one more edge tight.

Augmenting path. When the tree reaches a free column, the flip along way adds one matched pair and keeps all the others, so after row i rows 1 to i are matched. The costs are integers, so the total is exact.

In a solvable position the matching bound never exceeds the pushes really left. A real solution gives each box its own goal, and the pushes a box makes are at least its push distance to that goal, so the solution's total is one of the pairings the minimum ranges over. A* therefore stays optimal. The algorithm is checked against a brute force over every permutation of random cost matrices up to 5 by 5. 6

Simple bound (nearest goal)

The simple bound sums, over the boxes, the cost of the nearest goal for each box. It needs one minimum per box and no pairing, so two boxes may choose the same goal. Dropping the one-goal-per-box rule makes it a relaxation of the matching bound, so it is never larger.

h_{\text{simple}}(B) = \sum_{b \in B} \min_{g \in G} c(b, g)
7

Here G is the set of goals, and c(b, g) is the cost defined in the matching section. The bound is also admissible, because each box needs at least its cheapest cost to any goal.

7 
function SIMPLE-BOUND(boxes):
    total ← 0
    for each box b in boxes:
        total ← total + the smallest cost[b][g] over the goals g
    return total                                  # two boxes may claim one goal
function SIMPLE-BOUND(boxes):
    total ← 0
    for each box b in boxes:
        row ← cost[b]                             # one entry per goal, from BUILD-TABLES
        total ← total + min(row)
    return total

The simple bound is never larger than the matching bound, since every pairing's total is at least the sum of each box's cheapest cost. It is weaker when boxes compete for the same goal, and the benchmark shows the effect: A* with it expands 10,907 nodes across all 12 levels with pruning on, against 154 with the matching bound.

Push distances and dead squares

The push distance from a square x to a goal g is the fewest pushes that move a single box from x to g, with the other boxes ignored. It is computed by a backward breadth-first search from each goal, which runs the push rule in reverse: a box on y could have been pushed there from x = y - \delta if x and the square x - \delta behind it are floor.

d_g(g) = 0, \qquad d_g(x) = 1 + \min\bigl\{\, d_g(x + \delta) \;:\; \delta \in \{-w, +w, -1, +1\},\ x \text{ and } x - \delta \text{ are floor},\ d_g(x + \delta) \text{ is defined} \,\bigr\}
8

Here w is the padded width of the grid, so \pm w steps one row and \pm 1 one column. The minimum is over the neighbours x + \delta that already have a distance. The breadth-first order makes this the shortest push count, and an undefined distance means no push path exists. The search ignores the other boxes, so each distance is a lower bound on the real pushes.

A floor square with no defined distance to any goal is a dead square: a box there can never reach a goal, so the state is a deadlock.

\text{dead}(i) = 1 \iff d_g(i) \text{ is undefined for every goal } g \in G
9

Here i is a floor square and G is the set of goals. The goal squares themselves have distance 0 and are never dead.

The cost c(i, g) used by both bounds is the push distance when it is defined, and the Manhattan distance between the two squares otherwise, where (r_i, k_i) are the row and column of square i.

c(i, g) = \begin{cases} d_g(i) & \text{if } d_g(i) \text{ is defined} \\ |r_i - r_g| + |k_i - k_g| & \text{otherwise} \end{cases}
10

function PUSH-DISTANCES(level, goal):
    dist ← the push count from every square back to goal    # −1 when no push path exists
    queue ← [goal]
    while queue is not empty:
        y ← the front of queue
        for each direction d:
            x ← y − d                                       # the box came from x, pushed by d
            if x is floor and dist[x] is unset and x − d is floor:
                dist[x] ← dist[y] + 1
                append x to queue
    return dist
function PUSH-DISTANCES(level, goal):
    dist ← −1 for every square                    # −1 marks unreachable, the UNREACHABLE constant
    dist[goal] ← 0
    queue ← [goal]
    while queue is not empty:
        y ← remove the front of queue
        for each offset d in (−width, +width, −1, +1):
            x ← y − d                             # the box could have come from x
            if x is not floor or dist[x] ≠ −1:
                continue
            if x − d is not floor:                # the player must have stood at x − d
                continue
            dist[x] ← dist[y] + 1
            append x to queue
    return dist

function BUILD-TABLES(level):
    for each goal g: dist-g ← PUSH-DISTANCES(level, g)
    for each square i:
        if i is a wall:
            cost[i] ← empty;  nearest[i] ← −1
            continue
        entries ← empty;  feasible ← empty
        for each goal g in order:
            if dist-g[i] ≠ −1:
                append dist-g[i] to entries and to feasible
            else:
                append |row(i) − row(g)| + |column(i) − column(g)| to entries
        cost[i] ← entries
        if feasible is empty:
            dead[i] ← 1
        else:
            nearest[i] ← min(feasible)
    return dead, cost, nearest

Cost table. BUILD-TABLES runs PUSH-DISTANCES once per goal. The tables depend only on the walls and goals, so they are computed once per level layout and cached, and every starting position of that level reuses them. The Manhattan fallback keeps the cost finite for a pair that no push path joins, so the matching bound is defined when deadlock pruning is off. It stays a lower bound, because a real solution never pairs a box with a goal it cannot reach.

Frozen boxes and deadlock pruning

A frozen box is a box that no push can ever move again. A box can move along an axis only when both of its neighbours on that axis are free: one to stand on and one to slide into. A neighbour is blocked when it is a wall or a frozen box. A box is frozen when one of its two horizontal neighbours is blocked and one of its two vertical neighbours is blocked. The frozen set is the greatest set with this property. The code finds it by starting from every box and removing any box that is not blocked on both axes, until nothing changes.

B_F(c) = [c \text{ is a wall}] \lor [c \in F], \qquad b \in F \iff \bigl(B_F(b-1) \lor B_F(b+1)\bigr) \land \bigl(B_F(b-w) \lor B_F(b+w)\bigr)
13

Here F is the frozen set, B_F(c) is 1 when square c is blocked, and [\cdot] is 1 when its condition holds and 0 otherwise. The squares b \pm 1 are the left and right neighbours and b \pm w the upper and lower ones.

\text{deadlock}(B) = \bigl[\exists\, b \in B : \text{dead}(b) = 1\bigr] \lor \bigl[\exists\, f \in F(B) : f \notin G\bigr]
14

Here F(B) is the frozen set of the box layout B. A position is a deadlock when a box sits on a dead square, or when a frozen box is not on a goal. A frozen box on a goal is harmless. The test ignores the player, so it is sound: it never flags a solvable position.

15 
function FROZEN-BOXES(boxes):
    frozen ← boxes                              # assume every box is frozen
    while some box b in frozen is not blocked on both axes:
        remove b from frozen                     # b can move, so it is not frozen
    return frozen
function FROZEN-BOXES(level, boxes):
    frozen ← boxes
    changed ← true
    while changed:
        changed ← false
        for each b in a copy of frozen:            # the copy is taken at the start of the pass
            left-blocked ← (b − 1 is a wall) or (b − 1 in frozen)
            right-blocked ← (b + 1 is a wall) or (b + 1 in frozen)
            up-blocked ← (b − width is a wall) or (b − width in frozen)
            down-blocked ← (b + width is a wall) or (b + width in frozen)
            if not ((left-blocked or right-blocked) and (up-blocked or down-blocked)):
                remove b from frozen
                changed ← true
    return frozen

function IS-DEADLOCK(level, boxes):
    for each box b in boxes:
        if b is a dead square:
            return true
    for each frozen box f in FROZEN-BOXES(level, boxes):
        if f is not a goal:
            return true
    return false

Why a removed box can move. A box with a free side on some axis can move there if the player reaches the other side, so dropping it from the set is always justified. The boxes left in the set are stuck: each one's first move would need a blocking neighbour to move first, and none of them ever does.

Example. Four boxes in a 2 by 2 block, with the goals outside it, are all frozen and none is on a goal, so the position is a deadlock. 16
