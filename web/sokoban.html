HOW IT SEARCHES
THE MOVES ARE PUSHES
Walking is free: the player's reachable region is one state. Only pushes create new states, so the search depth is the push count.
DEAD SQUARES
Pull every goal backwards along valid pushes. A square no pull reaches is dead: a box there can never be moved to a goal.
FROZEN BOXES
A box blocked (by a wall or another frozen box) on at least one side horizontally and at least one side vertically can never be pushed again. Frozen off-goal means a deadlock, including the 2x2 block.
MATCHING BOUND
Each box must end on its own goal. The cheapest one-to-one pairing of boxes and goals (Hungarian algorithm) never undercounts the pushes left.

HOW IT WORKS

The solver searches over pushes, not steps, because walking is free. One search loop runs three ways (A*, greedy, breadth-first), and two lower bounds on the pushes still needed, plus deadlock checks, keep it away from positions that cannot be finished.

A* search

New to this? A* plans like a driver who adds the miles already driven to a guess of the miles still to go, and always tries the route with the smallest total first. If the guess never overstates the distance left, the first destination reached is by the shortest route.

Each state is a box layout, and its priority is g + h: pushes so far plus the bound. The page's default is A* with the matching bound and pruning on. Those controls drive HINT and SOLVE, and COMPARE runs both pruning settings.

  • The bound never overestimates, so the first goal taken off the queue has the fewest pushes.
  • Across all 12 levels, matching with pruning expands 154 nodes; without pruning, 269.

Greedy best-first

New to this? Greedy search is A* without the distance already travelled. It always heads for whichever option looks closest to done. That makes it quick, but a path that looks close can be a dead end, so the plan it returns can be longer than the best one.

Its priority is h alone, with g only breaking ties. The benchmark pairs it with the matching bound.

  • It solves all 12 levels with pruning on and off, but 11 of the 12 plans are optimal.
  • On the Aisle level it returns a 20-push plan where the optimum is 18.

Breadth-first search

New to this? Breadth-first search checks every position one push away, then every position two pushes away, like ripples from a dropped stone. It always finds the fewest pushes, but it never looks toward the goal.

Its priority is the push count g alone, with no heuristic. It is the baseline for the node counts.

  • With a 20,000-node budget it solves 8 of 12 levels with pruning off and 10 of 12 with pruning on.

Matching bound (Hungarian)

New to this? Suppose five people each need one of five chairs, and every person walks a different distance to every chair. The Hungarian algorithm finds the seating with the least total walking exactly, without trying every seating.

h is the minimum total push distance over all one-to-one pairings of boxes and goals, so no two boxes can claim the same goal. It runs in O(n³) for n boxes.

  • It never exceeds the pushes really left, so A* stays optimal.
  • tests/test_sokoban.py checks it against brute force over every permutation.

Simple bound (nearest goal)

New to this? It is like estimating a delivery round by adding up each parcel's distance to its nearest drop-off. The sum is easy to get, but two parcels may pick the same drop-off, so the total can come out too low.

h is the sum over boxes of the push distance to the nearest goal. It is admissible but weaker than the matching bound.

  • A* with it expands 10,907 nodes across all 12 levels with pruning on, against 154 with the matching bound.

Deadlock pruning

New to this? Some positions are lost before the search goes further. A sofa carried into a room corner, against two walls, can never be pulled back out. Spotting such positions early means the search never explores the hopeless branch below them.

Dead squares come from a backward search from each goal: a box on any other square can never reach a goal. A frozen box has a wall or frozen box on one horizontal side and one vertical side, so it can never move; off a goal, that is a deadlock. Pruning drops such a successor before it is stored.

  • Pruning never removes a solvable state, so the optimal push count is the same either way.

How these were chosen: none is tuned or learned. The push distances, dead squares and frozen-box test follow from the push rule, and the matching total is the exact minimum for its relaxation. The Manhattan fallback is a deliberate choice that keeps the bound finite when pruning is off; it can break consistency, so the search reopens a state that a cheaper path reaches later. The 20,000-node and 5 s caps bound CPU per request on the shared server (server/sokoban_api.py). Levels 1 to 7 are hand-drawn; levels 8 to 12 were generated, keeping the scramble with the most optimal pushes among 40 seeds.
