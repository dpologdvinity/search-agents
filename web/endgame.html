HOW IT WORKS

The tablebase does not search. It is a complete table of every position in these endgames, built offline by retrograde analysis: a method that starts from the finished positions and works backwards. Each position gets its exact distance to mate, the number of moves to checkmate with best play on both sides, or is marked as a draw. Playing is then a lookup. The chance opponent does not read the table at all: it draws each legal move from fixed odds.

Endgames and the table

The two endings are KQK, a white king and queen against a lone black king, and KRK, a white king and rook against a lone black king. The pieces move as in chess, with no pawns, so there is no promotion and no castling. The black king is alone, so its only capture is taking the white piece. That leaves king against king, which is a draw, a position where neither side can force mate.1 The 50-move rule is not applied, so every distance is pure distance to mate.2

A position is a tuple: the white king's square, the white piece's square, the black king's square, and the side to move. Squares are numbered 0 to 63 with a1 = 0, b1 = 1 and h8 = 63. The square number is 8 × rank + file, both counted from 0.3 The table has one entry for each tuple, so it holds 2 · 64³ = 524,288 entries, or 1 MiB as uint16 values. Only some tuples are legal positions: 368,452 for KQK (70%) and 399,112 for KRK (76%). The others repeat a square, put the two kings next to each other, or leave the side not to move in check.4 Each tuple has a fixed place in the table, given by this index:

\text{index}(w_k, w_p, b_k, s) = 2\bigl(64\,(64\,w_k + w_p) + b_k\bigr) + s
5

Here w_k is the white king's square, w_p the white piece's square, b_k the black king's square, and s the side to move, 0 for White and 1 for Black. The index is a row number, so a lookup is one array access.

Retrograde analysis

Retrograde analysis solves a game from its end. Forward search asks what follows from a position, and needs the whole game tree. Retrograde analysis asks the reverse question: which positions lead to a decided one. The solver6 works in three passes over the table. Its inputs are the legal positions, and its outputs are one code per entry.

Pass 1 finds every legal position.7 A position with a legal move starts as UNKNOWN, with a counter equal to its number of legal moves, captures included. A checkmate (no legal move, and the side to move in check) is decided at once with value 0 and joins the queue. A stalemate (no legal move, not in check) is a draw.

Pass 2 takes decided positions from a first-in, first-out queue.8 Each new entry is one ply deeper than the entry that produced it, so the queue stays in order of distance to mate. For each popped position, the solver visits its predecessors: the legal positions from which one non-capturing move reaches it. If the popped position is lost for its side to move, every undecided predecessor is a win one ply deeper. If it is won for its side to move, the move into it is bad for the predecessor, so the predecessor's counter drops by one. When a counter reaches zero, every move from that predecessor loses, and the predecessor is a loss one ply deeper than the last winning reply, which is the deepest one.

Pass 3 marks every position still undecided as a draw, because no sequence of moves forces mate from it.9

function RETROGRADE-SOLVE(piece):
    for each legal position P:
        if P has a legal move:
            value[P] ← UNKNOWN;  count[P] ← number of legal moves of P
        else if P is checkmate:
            value[P] ← 0;  add P to the queue
        else:
            value[P] ← DRAW                        # stalemate
    while the queue is not empty:
        S ← remove the front of the queue
        for each predecessor P of S:
            if value[P] is UNKNOWN:
                if value[S] is even:               # S is lost for its side to move
                    value[P] ← value[S] + 1;  add P to the queue
                else:                              # S is won, so one move of P is bad
                    count[P] ← count[P] − 1
                    if count[P] = 0:               # every move of P loses now
                        value[P] ← value[S] + 1;  add P to the queue
    for each position P with value[P] = UNKNOWN:
        value[P] ← DRAW

function RETROGRADE-SOLVE(piece):
    value ← ILLEGAL for every entry;  count ← 0 for every entry;  queue ← empty
    for wk in 0 to 63:                                   # pass 1, in index order
        for wp in 0 to 63:
            if wp = wk: continue
            for bk in 0 to 63:
                if bk = wk or bk = wp: continue
                for stm in (WHITE, BLACK):
                    P ← (wk, wp, bk, stm)
                    if not IS-LEGAL(piece, P): continue
                    moves ← LEGAL-MOVES(piece, P)
                    if moves is not empty:
                        value[P] ← UNKNOWN;  count[P] ← number of moves      # captures included
                    else if IN-CHECK(piece, P):
                        value[P] ← 0;  add P to queue                         # checkmate
                    else:
                        value[P] ← DRAW                                       # stalemate
    while queue is not empty:                            # pass 2
        S ← remove the front of queue
        d ← value[S]
        for each P in PREDECESSORS(piece, S):
            if value[P] ≠ UNKNOWN: continue              # decided already, or a draw
            if d mod 2 = 0:                              # S is lost for its side to move
                value[P] ← d + 1;  add P to queue
            else:                                        # S is won for its side to move
                count[P] ← count[P] − 1
                if count[P] = 0:                         # every move of P loses now
                    value[P] ← d + 1;  add P to queue
    for each entry with value UNKNOWN:                   # pass 3
        value ← DRAW
    return value

The counter. The counter of a position is the number of its legal moves that have not yet been shown to be bad. A capture is one of those moves, but it never decrements the counter. It ends in king against king, a draw, so it can never make the position lost for the side that captures, and the counter keeps that position from being declared lost by mistake.

Why the queue gives the right number. The first lost successor found for a position is the one with the smallest distance, since the queue is in order, so it gives the fastest win. The last winning successor to bring the counter to zero is the one with the largest distance, so it gives the longest defence.

Predecessors. The solver walks backwards, so it needs the positions one quiet move earlier. These are generated by reversing the move rules. A king steps back to a neighbouring square. A piece slides back along the lines it could have travelled, with the same blockers, so it can stand on any square from which it reaches the current one. Each candidate is kept only when it is a legal position.11

11 
function PREDECESSORS(piece, S):
    if Black is to move in S:                # White just moved
        candidates ← the squares next to the white king, and the squares the piece slides to
    else:                                    # Black just moved
        candidates ← the squares next to the black king
    return the candidates that are legal positions
function PREDECESSORS(piece, S):           # S = (wk, wp, bk, stm)
    out ← empty list
    if stm = BLACK:                          # White just moved
        for each neighbour a of wk:          # the white king stepped from a
            if a ≠ wp and a ≠ bk: add (a, wp, bk, WHITE) to out
        for each square a the piece can slide to from wp, stopped by wk and bk:
            add (wk, a, bk, WHITE) to out    # the piece stepped from a
    else:                                    # Black just moved
        for each neighbour a of bk:          # the black king stepped from a
            if a ≠ wk and a ≠ wp: add (wk, wp, a, BLACK) to out
    return the candidates in out for which IS-LEGAL(piece, candidate) holds

The rule for a decided position. Pass 2 applies one rule to each predecessor P of a decided position S. Let d(X) be the value of X in plies, and let N(P) be the set of positions reached from P by one legal move that is not a capture. The value of P is:

d(P) = \begin{cases} 1 + \min\{\, d(S) : S \in N(P),\ d(S) \text{ even} \,\} & \text{if some } S \in N(P) \text{ has } d(S) \text{ even} \\ 1 + \max\{\, d(S) : S \in N(P) \,\} & \text{if every legal move of } P \text{ leads to an odd } d(S) \end{cases}
12

Here an even d(S) means the side to move in S is mated, and an odd one means it wins. The first case is a win for P: the move into the lost position S with the fewest plies gives the fastest mate. The second case is a loss for P: every move leads to a win for the opponent, and the slowest of those wins sets the defence. A capture or a move into a draw blocks the second case, since neither has an odd distance. A drawn successor has no distance at all, so it is neither even nor odd, and the first case ignores it. A position that neither case decides stays a draw. Each value in the table is the number of plies, and the checkmate is d = 0.

Distance to mate and the codes

Each entry is a code stored as a uint16. A real code is a distance to mate in plies, which are half-moves, and real codes are below 100 plies.13 An odd code means the side to move wins in that many plies. An even code means the side to move is lost, and 0 means it is already checkmated. Three codes sit above the real range, so no distance can collide with them. 65533 (UNKNOWN) appears only while the solver runs, and every one is replaced by a draw before the table is saved. 65534 (DRAW) marks a drawn position, and 65535 (ILLEGAL) marks a tuple that cannot occur.14

People count moves, not plies. A win in d plies is a mate in the number of moves below for the side to move, and the same formula gives the moves a lost side lasts:

\text{moves}(d) = \left\lfloor \dfrac{d + 1}{2} \right\rfloor
15

Here d is the code in plies, and the floor division keeps whole moves. A win in 19 plies is mate in 10 moves, and the longest defence in KQK is 20 plies, which is also 10 moves.2

Table lookup and the tablebase's choice

The tablebase does not search. To choose a move, it asks what the position after each legal move is worth. The stored code describes the side to move in that position, which is the opponent of the mover, so the result is flipped. An even code (the opponent is mated) is a win for the mover, and an odd code is a loss. A code of 0 means the move gives checkmate, which the page marks with #. A capture of the piece, or a move into a drawn position, gives a draw.16 The distance of a move, d(m), counts from the mover's own move, so it is the code plus one.17

The tablebase then plays the move with the largest key. The key ranks a move for the mover. A win beats a draw, and a draw beats a loss. Among wins the fewest plies is best, and among losses the most plies is best:

K(m) = \begin{cases} (2,\ -d(m)) & \text{if } m \text{ wins} \\ (1,\ 0) & \text{if } m \text{ draws} \\ (0,\ d(m)) & \text{if } m \text{ loses} \end{cases}
18

Here d(m) is the distance to mate after move m, counted in plies from the mover's move. Keys are compared as pairs: the first number is the outcome class, and the second breaks ties inside it. Because one key serves both sides, the same rule gives the fastest mate when the tablebase is winning, the longest defence when it is lost, and a drawing move when one exists. The best move is the maximum key.19 On a tie, max keeps the move that was generated first.

function BEST-MOVE(position):
    for each legal move m:
        outcome, plies ← the result of m, seen by the mover
    return the move with the largest key (win beats draw beats loss,
           then fewest plies for a win and most plies for a loss)
function BEST-MOVE(position):
    best ← none;  best-key ← none
    for each move m in LEGAL-MOVES(position):             # generation order
        if m takes the white piece:                       # king against king
            outcome ← draw;  plies ← none
        else:
            code ← TABLE[RESULT(position, m)]             # the opponent's view
            if code = DRAW:
                outcome ← draw;  plies ← none
            else:
                plies ← code + 1
                if code is even: outcome ← win            # the opponent is mated
                else:            outcome ← loss           # the opponent wins
        if outcome is win:    key ← (2, −plies)
        else if outcome is draw: key ← (1, 0)
        else:                 key ← (0, plies)
        if best is none or key > best-key:                # strict: ties keep the first
            best ← m;  best-key ← key
    return best

Example. Suppose the table gives two winning moves in a KQK position: one with d = 3, a mate in two, and one with d = 19, a mate in ten. Their keys are (2, -3) and (2, -19). The first is larger, so the tablebase plays the mate in two.

Chance (fixed odds)

The chance opponent plays with fixed odds and no search, no evaluation and no table lookup. The odds depend only on what kind of move each legal move is. A move gets one category, and the first category that fits is used, in this order: capture (the lone king takes the piece), check (the move gives check), king step toward the centre (a king move that brings the king closer to the middle of the board), and other (every remaining move).20 The weights are 4 for a capture, 2 for a check, 2 for a king step toward the centre and 1 for any other move.21 They are a fixed bias. Nothing reads the position beyond the category.

The king step test uses a distance to the centre, C(q), computed for a square q:

C(q) = \max\bigl(\,|2f - 7|,\ |2r - 7|\,\bigr)
22

Here f and r are the file and rank of q, both counted from 0. C is the Chebyshev distance from the centre, the number of king steps needed to reach it, doubled so it stays an integer. The four central squares d4, e4, d5 and e5 give 1, and the edges give 7. A king step is toward the centre when it lowers C.

A legal move m in a position with legal moves M is drawn with this chance, where w(m) is the weight of its category:

P(m) = \dfrac{w(m)}{\sum_{m' \in M} w(m')}
23

The sum is over the legal moves only, so the table is renormalised for each position and the chances sum to 1. The table is never used directly, only its shares. For example, with one legal move in each category, the weights 4, 2, 2 and 1 give chances of 4/9, 2/9, 2/9 and 1/9.24

The draw uses a uniform number u in [0, 1) and the cumulative weights. With W = \sum_{m' \in M} w(m'), the move m_i is chosen when:

\sum_{j < i} w(m_j) \le u\,W < \sum_{j \le i} w(m_j)
25

Each move owns a slice of the interval from 0 to W whose length is its weight, and u picks the slice. The same rule is in the page's endgame-core.js, a line-for-line port,26 and tests/test_endgame_parity.py checks that both choose the same move for the same numbers.27 The page draws u from a seeded mulberry32 generator,28 and each new game takes the next seed.29 The offline match uses Python's generator, seeded per position.30

function CHANCE-MOVE(position, u):           # u is uniform in [0, 1)
    moves ← LEGAL-MOVES(position)
    total ← sum of WEIGHT(m) over moves
    threshold ← u × total
    acc ← 0
    for each move m in moves:
        acc ← acc + WEIGHT(m)
        if threshold < acc: return m
    return the last move                        # reached only through rounding
constants: CAPTURE = 4, CHECK = 2, KING-CENTRE = 2, OTHER = 1

function CATEGORY(position, m):                 # the first category that fits wins
    if m is the black king taking the white piece: return "capture"
    if m leaves the other side in check:           return "check"
    if m is a king move and CENTRE(to of m) < CENTRE(from of m):
                                                   return "king_centre"
    return "other"

function CENTRE(sq):
    f ← file of sq;  r ← rank of sq             # both counted from 0
    return max(|2 × f − 7|, |2 × r − 7|)

function CHANCE-MOVE(position, u):              # u is uniform in [0, 1)
    moves ← LEGAL-MOVES(position)
    for each move m in moves:
        weight[m] ← the weight of CATEGORY(position, m)   # 4, 2, 2 or 1
    total ← sum of weight[m] over moves
    threshold ← u × total
    acc ← 0
    for each move m in moves:                   # in generation order
        acc ← acc + weight[m]
        if threshold < acc: return m
    return the last move                        # reached only through rounding

Category order. The first category that fits is used, so a king move that also gives check is counted as a check. The code's comment gives the reason for the largest weight: a capture ends the game as a draw for the lone king, so it is the most tempting move, and it gets the most weight.31

The walk. pick_at keeps a running sum of the weights and returns the first move whose running sum passes u \times W. That is the same as the slice rule above, and it needs only one pass over the moves.32 The final return is a guard for floating-point rounding, when u is very close to 1.

Watch mode and the match

Watch mode plays a game with no moves from you. Each game starts from a random winning position for the side with the piece, and TABLEBASE PLAYS chooses the side the tablebase takes. The chance opponent takes the other side. A game ends by checkmate, by a draw (a capture of the piece or a stalemate), or after 300 plies. A game that reaches 300 plies is counted as unfinished, since the chance side can hold out in an endless line.3334 The score counts the tablebase's wins, draws, losses and unfinished games.35 With AUTO-RESTART on, the next game starts 1.8 s after the end.3637 PAUSE stops after the current move, and STEP plays one move while the game is paused.38 The heat map is off in watch mode, since it would double the requests for each move.39

Checking the table

A checker verifies each entry against the definition of distance to mate, without calling the solver. It looks at every legal position P with stored value v, and lists the outcome of each legal move from the mover's side, with d(m) the plies to mate after the move. Let W be the set of d(m) for winning moves, L the set for losing moves, and D the number of drawing moves. The entry is valid when:

\begin{cases} v = \text{DRAW} & \Rightarrow\ W = \varnothing \text{ and } D \ge 1 \\ v \text{ odd} & \Rightarrow\ W \ne \varnothing \text{ and } \min W = v \\ v \text{ even} & \Rightarrow\ D = 0,\ W = \varnothing,\ L \ne \varnothing \text{ and } \max L = v \end{cases}
4445

The first line says a draw has at least one drawing move and no winning move. The second says a win is exact: its fastest winning move must be exactly v. The third says a loss is exact: no move draws or wins, and the slowest reply must be exactly v. A checkmate must store 0, and a stalemate must store DRAW.46

function CHECK-TABLE(piece, table, positions):
    problems ← empty list
    for each position P:
        v ← table[P];  W, L, D ← the winning, losing and drawing moves of P
        if P has no legal move:              # checkmate or stalemate
            expected ← 0 if P is checkmate else DRAW
            if v ≠ expected: add a problem
        else if the rule for v fails (see the formula above):
            add a problem
    return problems
function CHECK-TABLE(piece, table, positions):
    problems ← empty list
    for each position P in positions:
        v ← table[P]
        moves ← LEGAL-MOVES(piece, P)
        if moves is empty:                              # terminal position
            expected ← 0 if IN-CHECK(piece, P) else DRAW
            if v ≠ expected: add a "terminal" problem
            continue
        results ← empty list
        for each move m in moves:
            S ← RESULT(P, m)
            if S is none: add draw to results            # capture: king against king
            else if table[S] = DRAW: add draw to results
            else if table[S] is even: add (win, table[S] + 1) to results
            else: add (loss, table[S] + 1) to results
        wins ← plies of the win entries;  losses ← plies of the loss entries
        draws ← number of draw entries
        if v = DRAW:
            if wins is not empty or draws = 0: add a "draw" problem
        else if v is odd:
            if wins is empty or min(wins) ≠ v: add a "win" problem
        else:
            if draws > 0 or wins is not empty or losses is empty or max(losses) ≠ v:
                add a "loss" problem
    return problems

Why check. The checker shares only the rules with the solver, not its code. A table that the solver got wrong would fail the definition, so a clean report is evidence that the table satisfies the rules at every entry. python -m endgame build runs it after every rebuild.48 It reports 0 problems in 368,452 KQK entries and 0 problems in 399,112 KRK entries.2 As a test of the checker itself, 20 corrupted entries in a copy of the table gave 51 reported problems.2 The predecessor generator was checked as the exact inverse of the move generator, with 4,869,496 quiet edges in each direction for KQK and no mismatches.
