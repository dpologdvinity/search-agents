HOW IT WORKS

A nonogram gives one clue per row and one per column: the lengths of the runs of filled cells, in order. The search has to find the grid whose runs match every clue. This page runs three methods. Line solving reads one row or column at a time and proves the cells it can. SAT turns the whole grid into clauses and runs DPLL. Hybrid combines the two: propagate lines, guess a cell, and backtrack.

1. Line solving

New to this? A clue such as 3 1 says the row has a run of three filled cells, a gap, and then one filled cell. The solver lists every way the clue can be placed on the cells, throws out placements that clash with what is already known, and keeps the cells that every surviving placement agrees on.

Each clue is a regular language. It is a finite automaton over 0 and 1 with states: k runs done, no run open, inside run k with j cells, and run just ended, gap required. A forward pass marks the states reachable from the start while reading the known cells. A backward pass marks the states that can still reach an accepting end. A cell can be 1 if some reachable transition on a 1 leads to a co-reachable state, and it can be 0 by the same test. Both passes are dynamic programming over positions, so one line costs O(length × runs).

The solver sweeps all rows, then all columns, and repeats until nothing changes. This is a fixed point: the cells proved so far are the only ones the lines can force.

2. SAT encoding

New to this? SAT asks whether some true-or-false assignment to the variables makes every clause true. Here one variable says whether a cell is filled, and the clauses say that each line's clue holds.

Per line, the automaton from method 1 is unrolled over positions. A state variable s[i][q] means "after reading i cells the automaton is in state q". Only states that are both reachable and co-reachable get a variable, which keeps the encoding small. A transition variable ties each state to the next cell, and a biconditional clause set makes each transition variable equal the cell value that triggers it. The clue holds exactly when the automaton ends in an accepting state, which is one unit clause. Every variable and clause is counted, and the counts are reported live.

The encoding is clause-by-clause: a line of length L with S live states gives about L × S variables and a constant number of clauses per position.

3. DPLL with unit propagation

New to this? DPLL picks a variable, guesses a value, and follows the consequences. If a clause becomes empty, the guess was wrong and the solver undoes it, then tries the other value. Unit propagation is the rule that when a clause has only one unassigned literal left, that literal must be true, so it costs nothing to set.

The solver first removes pure literals, which are variables that appear with only one sign and can be set to that sign safely. It then searches with two watched literals per clause, so propagation only visits clauses whose watch became false. Branching uses VSIDS-lite: each variable has an activity score, bumped when it takes part in a conflict and decayed after every conflict. Cell variables start with activity 1.0, so the search decides cells before the automaton helpers. Phase saving reuses the last value a variable had. Backtracking is chronological: no clause learning, so a conflict undoes the most recent guess and nothing else.

4. Hybrid

New to this? Hybrid is the middle ground. It uses the cheap line rules as often as possible and only guesses when they stall. A guess that breaks a line is caught right away, so the search tree stays small.

Propagation runs line solving to a fixed point. If cells are still unknown, the solver picks the first unknown cell of the line with the fewest unknowns, tries 1 and then 0, and recurses. Each branch re-runs propagation, and a line with no placement left is a contradiction that undoes the guess. A node budget stops the search, and the answer is then reported as undecided rather than guessed.

5. Uniqueness

New to this? A good puzzle has exactly one picture that fits the clues. To check, the solver finds one picture, then searches for a second one that differs in at least one cell. If none exists, the puzzle is unique.

SAT adds a blocking clause that forbids the cell values of the first picture, then solves again. If that is unsatisfiable, there is no second picture. Hybrid counts solutions instead, and stops at two. Random pictures are kept only when this check passes within its node budget.
