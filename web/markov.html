HOW IT WORKS

A Markov chain writes text by looking only at the last few tokens. Here the model is nothing but counts: for every run of n-1 words in a corpus, how often each word followed it. Generating means reading the current context, drawing the next word in proportion to those counts, and repeating. The page runs a JavaScript port of the Python package markov, which reproduces the same tokens for a corpus, order, temperature and seed.

Counting what follows

New to this? Read a book and put a finger on a phrase. Write down the word that comes next. Do it for every phrase. The table you end up with is the whole model: each phrase, and a tally of its followers.

An n-gram is n consecutive tokens. For order n, the corpus is cut into every window of n tokens. The first n-1 tokens are the context and the last is the successor, and the model keeps count[context][successor]. With the tiny text "a b a b a c", the order-2 table is a → {b: 2, c: 1} and b → {a: 2}.

The Markov assumption

New to this? Pretend the next word only cares about the last few words, and forgets everything before. That is a lie, but a useful one: it makes the table small enough to store and the sentences still look plausible.

Formally, P(next | everything so far) is replaced by P(next | last n-1 tokens). The order n is the size of the memory. Order 1 remembers nothing, and order 5 remembers four words. Character-level chains do the same with letters, so the memory is four characters, not four words.

Sampling and temperature

New to this? Rolling dice weighted by the table. A phrase followed by "the" nine times and "a" once gives "the" nine chances in ten. Temperature turns the knob on that weighting: cold makes the favourite almost certain, hot makes every follower about as likely.

Each count c becomes c^(1/T) before normalising, so T = 1 uses the raw counts, T below 1 sharpens the distribution and T above 1 flattens it. Each token uses one uniform draw from a seeded generator (mulberry32, the same one as the bandits lab), so a seed replays a run exactly.

Order and copying

New to this? At order 5 each four-word phrase in the output almost always occurs in the book already. The chain is not writing new sentences; it is stitching together passages it has seen, with the seams hidden. The copy meter measures how often that happens.

A generated window of n tokens is a copy if it occurs in the corpus. The meter reports the share of copied windows at the current order, and the longest verbatim run: the longest stretch that occurs in the corpus, capped at 20 words. A run can only be a copy if every shorter window ending at the same place is a copy too, which lets the check stop early.

Perplexity and overfitting

New to this? Perplexity is how surprised a model is by text, as an effective number of choices per word: lower is better. Score a model on the text it learned from and the number falls as the order grows, because the table memorises it. Score it on text it never saw and the number falls, then climbs again: a phrase the book never had leaves the model guessing, and high orders only repeat the book. On the Alice excerpt the held-out score is lowest at order 2 (209) and is 291 at order 3 and 380 at order 5. The gap between the two numbers is the overfitting.

Perplexity is exp of the mean negative log probability per token. Unseen phrases get add-alpha smoothing (alpha 0.01 here, so train scores are not drowned out). The command python -m markov perplexity --corpus alice --order 1..5 prints train and held-out scores side by side. The held-out tail is the last 10% of tokens.

From counts to language models

New to this? Chatbots and other large language models also predict the next token, one at a time, and they also sample it with a temperature. The difference is the memory: they do not store a table of phrases. They learn a function that turns the whole context into a distribution over tokens, so they can use a context they have never seen word for word.

A Markov chain is a language model whose context is limited to n-1 tokens and whose probabilities are counts. A modern model uses a much longer context (thousands of tokens) and computes the probabilities with a neural network, trained to lower the same negative log probability that perplexity measures. The sampling loop is the same: score the candidates, draw one, append it, repeat.

How these were chosen: The corpora are short so that a page can hold one in memory and the copy meter is easy to read. The order range stops at 5 because order 5 already copies almost everything from a corpus this size. The temperature range keeps 0 out of the formula, since c^(1/0) is undefined. The smoothing alpha is small on purpose: Laplace smoothing (alpha 1) spreads so much mass over the vocabulary that train perplexity rises again at order 3, which hides the overfitting the table is meant to show. None of these values was tuned on held-out text.
