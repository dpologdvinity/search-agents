    HOW THEY PLAN
    CONFLICT-BASED SEARCH
    Plan every robot alone. When two collide, split: one branch forbids the first robot from that cell at that moment, the other forbids the second. Replan only the robot that was constrained. The cheapest tree node with no collisions is the optimal plan.
    PRIORITIZED
    Plan robots one at a time. Each later robot treats the earlier paths as moving obstacles. Always collision-free, but a robot can be boxed in, and early greedy routes make the total longer.
    INDEPENDENT A*
    Each robot takes its own shortest path and ignores the others. Instant, and the red flashes show every place that breaks the rules.

    HOW IT WORKS

    Robots move one cell or wait each time step, and may never share a cell or swap places. The page compares three planners on one instance: Conflict-Based Search (optimal), prioritized planning, and independent A*. CBS plans every robot alone, finds the first collision, and adds a rule only for the robots involved.

    Conflict-Based Search (CBS)

    New to this? Picture delivery drivers who each know their fastest route, but two of those routes cross at the same corner at the same moment. At the first crash, split into two plans: in one, the first driver is barred from that corner at that moment; in the other, the second driver is. Always work on the cheapest open plan until one has no crashes.

    The high level is a constraint tree. The root plans every robot alone, so its total cost is a lower bound on every later node. The earliest collision between robots i and j creates two children, each adding one constraint to one of the two robots. Only that robot is replanned. Nodes are expanded cheapest first by sum of costs, so the first collision-free node is optimal: every collision must be resolved by one of its two children.

    • Vertex conflict: two robots on one cell at one step. Edge conflict: two robots swap cells in one step.
    • Budget: 2,000 nodes and 2.0 s on the page. If either runs out, the page reports the status and shows no plan.

    Space-time A* (the planner inside CBS)

    New to this? A* is a route-finding method. It always expands the option with the lowest score: distance travelled so far plus a guess of what remains, the same idea as a road map app. Here time is part of the map too, because a robot can wait, so a cell at time 3 is a different state from the same cell at time 4.

    Each state is a (cell, time) pair. Moves go to a free neighbour or stay put. Forbidden states come from a reservation table: a vertex block keeps a robot off a cell at a time, and an edge block stops a swap. The guess is the shortest walking distance to the goal, ignoring other robots. It never overestimates, so the first valid goal state popped arrives earliest. A goal state is valid only if the robot can stay there afterwards.

    Prioritized planning

    New to this? Think of people leaving a building through one hallway. The first person picks a path, and each later person walks around the people already committed. It is quick, but the last person can find every route blocked.

    Robots are planned in index order, robot 0 first. After each one, its whole path, including the cell it parks on, goes into the reservation table, and the next robot plans against it. Every returned plan is collision-free by construction. If a robot has no route, the status is failed and no plan is shown.

    Independent A* (baseline)

    New to this? Every driver takes the shortest route on the map and ignores everyone else. It is the fastest answer, but nothing stops two drivers reaching the same cell at the same moment.

    Each robot runs space-time A* with an empty reservation table. The paths are then checked for collisions. The page reports the status as collisions, not a plan, and flashes each collision on the step it happens. Its sum of costs looks lowest only because the plan it describes is invalid.

    How these were chosen: Nothing here is learned, and nothing is tuned: the repo has no tuning or sweep code for these values. The heuristic is the exact shortest-walk distance, so there was no value to pick. The budgets are constants set by hand. The server comments give the reasoning: a RANDOMIZE draw costs at most 10 × 0.4 s, about 4 s, and the page's solve budget is 2 s. The map and robot caps exist because the planners bound time but not size.

    Benchmark (README): bottleneck map, 6 robots, 10 instances: CBS averages a sum of costs of 52.9 with no collisions. Prioritized averages 55.9 and is suboptimal on 5 of 10. Independent A* averages 47.7 but leaves 3.80 collisions per instance. On shelf aisles with 8 robots: CBS 75.7, prioritized 79.5, independent 72.9 with 3.50 collisions. Rerunning both benchmarks matched these costs, collision counts, and solved counts.
