NOTES
HAND-TUNED VS LEARNED
The hand-crafted agent scores boards with six features (empty cells, monotonicity, corner, merges, smoothness, max tile), with weights found by an automated search over simulated games. The n-tuple network learned its own scoring from 45,514 self-played games (the last count the trainer logged).
CHANCE NODES
After each move a 2 (90%) or 4 (10%) appears in a random empty cell. Expectiminimax averages over every possibility, so the value shown is an expectation, not a guarantee.

HOW IT WORKS

The agents look a few moves ahead, averaging over the random tile that appears after each slide. One scores positions with six hand-chosen features whose weights were found by an automated search. The other is an n-tuple network: a table of values for small patches of the board, learned by playing games. The third combines the table with the same look-ahead.

Expectimax (tuned features)

New to this? Planning a route when some roads may be closed at random: for each choice, weigh every way the randomness could turn out by how likely it is, and pick the choice with the best average result.

Alternates player nodes, which choose a slide, with chance nodes, where a 2 (probability 0.9) or a 4 (probability 0.1) appears in each empty cell with equal chance. Iterative deepening runs up to depth 20 within 0.1 s per move. Leaves are scored by the tuned evaluation below.

N-tuple network (no search)

New to this? A cheat sheet that lists a score for every small patch of a board. To judge a position, look up each patch and add the scores, with no planning at all.

Six patterns of tile positions, each with its own table: four 5-cell patterns (16⁵ = 1,048,576 values each) and two 6-cell patterns (16⁶ = 16,777,216 values each). Each pattern is read under the 8 board symmetries, so a position costs 48 lookups. The move chosen maximises points gained plus the value of the resulting board. Trained by TD(0), below.

N-tuple + expectimax

New to this? Use the cheat sheet to judge positions at the end of a short look-ahead, so the planning and the table work together.

The expectimax search above, with the n-tuple value plus points gained along the line used as the leaf score. It is the default when the table is available.

How these were chosen: tuned automatically with the cross-entropy method (game2048/tune.py). Each generation draws candidate weight vectors from a Gaussian, scores each by the mean final score of greedy one-move-lookahead games on shared seeds, keeps the best elite, and refits the Gaussian to them. The table's weights are from an earlier, unbounded run whose settings were not recorded. The bounded runs used 20 generations, 32 candidates, 8 elite, 300 games per candidate, and seed 0 (python -m game2048.tune --generations 20 --population 32 --elite 8 --games 300 --seed 0). Final weights are rescaled so the largest is 1.0.

Sign note: every feature is oriented so that larger is better: the two penalties (monotonic, smooth) are zero or below. A negative weight on a penalty rewards the disorder it measures. The tuner now bounds every weight at zero. The table's smooth weight is negative because its run was unbounded, and the search rewards rougher boards on that term. A bounded re-run scored lower under greedy play (5,823 against 7,074 points on 3,000 held-out games; 95% intervals 5,709 to 5,936 and 6,930 to 7,219). Its expectimax score was higher by about 1,700 points on 60 held-out games, but the intervals overlap, so the table's weights were kept.

Expectimax with these features, 60 held-out games at 50 ms per move: mean 16,954 (95% CI 15,259 to 18,650), 2048 reached in 11.7% (5.8 to 22.2). The bounded set gave 18,639 (16,461 to 20,817) and 20.0% (11.8 to 31.8).

Patterns 5 and 6 are the 6-cell tuples of the 4 × 6-tuple network of Yeh et al. (the TDL2048 demo). The other two, cells 4, 5, 6, 7, 8, 9 and cells 4, 5, 6, 8, 9, 10, were left out to keep the 6-cell tables to two. The earlier network used six 5-cell patterns, and its patterns 5 and 6 were transposes of 3 and 4. Under the symmetry sum a transpose scores every board the same as its source, so that network had four distinct shapes.

The n-tuple network is trained by TD(0) on afterstates (game2048/train_td.py), with 1,000 games advancing in lockstep: python -m game2048.train_td --minutes 70 --games 1000 --alpha 0.1 --seed 0. After each move, the value of the previous afterstate moves toward the reward plus the value of the new one, with target 0 at game end. The learning rate is 0.1, split across the 48 lookups of each position, and updates are averaged per weight within a batch. Tables are float32 during training and stored as float16 (72 MiB in memory). The trainer logs once a minute and writes no final record, so the figures are its last logged record: 45,514 games at 69.04 minutes, with a mean score of 52,801 over the last 2,000 training games, 2048 reached in 86.4% and 4096 in 45.6%. The previous network's last record is 42,980 games at 64.1 minutes.
