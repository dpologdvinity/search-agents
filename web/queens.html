HOW THE FOUR AGENTS DIFFER

HOW IT WORKS

Four agents try to place N queens on an N × N board so that no two attack each other. Backtracking is exhaustive, so it can prove that no answer exists. The other three are local search: they start from a board with conflicts and move queens to reduce them, with no proof of anything. Min-conflicts is the one that scales: in the benchmark it solved a 1,000,000-queen board in one run of 13.6 s.

The problem and the conflict count

New to this? On a chessboard, a queen captures along its row, column and diagonals. The puzzle asks for N queens placed so none can capture another. Random placements almost never work for large N, so the agents have to search with some sense of direction.

The board keeps one queen per row, so only columns and diagonals can clash. A conflict is a pair of queens sharing a column or a diagonal. Three count arrays hold the number of queens on each column and each diagonal, so the change in conflicts from moving one queen is an O(1) lookup. A line holding k queens has C(k, 2) conflicting pairs, and a solution has zero.

Backtracking with bitmasks

New to this? Place queens one row at a time. If a row has no safe square, take back the queen above and try its next square. It is slow on big boards, but every partial board it keeps is conflict-free, and when it finishes it has either a solution or a proof that none exists.

For each row, three n-bit masks mark the columns already taken and the two diagonals hit by queens above. The open squares are full & ~(cols | ld | rd), and the lowest open bit is tried first. The search is iterative, so a board of 10,000 rows does not overflow Python's recursion limit. Being exhaustive, it reports "exhausted" when no solution exists, as it does for N = 2 and 3.

Steepest-ascent hill climbing

New to this? Look at every single queen move and take the one that removes the most conflicts. When no move helps, the search is in a dip or on a flat plateau, so it tips the board over and starts again from a random placement.

Each step scores every move (each row against each column), which is N × N squares, and plays one of the best, ties broken at random. Sideways moves are not allowed. A restart counts as a step and as a restart. The run stops when it solves the board or reaches its time cap.

Simulated annealing

New to this? Like a metal cooling into shape. Propose a random queen move. An improvement is always accepted. A worse move is sometimes accepted, and less often as the temperature falls. While hot the search can climb out of a dip, and once cold it settles.

A proposal moves one random queen to another random column. Its change in conflicts is d. A move with d ≤ 0 is always taken; an uphill move is taken with probability exp(−d / T). The temperature falls geometrically from T = 2.0 to 0.05 over a run of max(200, 60 N) proposals. A run that ends unsolved restarts from a random placement at T = 2.0.

Min-conflicts

New to this? Pick a queen that is under attack, lift it, and set it down in the square in its row with the fewest attacks. Repeat until nothing is attacked. Each repair scores the columns of one row, so it stays cheap even on enormous boards.

The start is greedy: each row tries up to 4,096 random unused columns and keeps the first with no attacks, or else the least attacked one. Each repair then picks a conflicted queen uniformly at random, removes it, scores every column in its row, and moves the queen to a least-attacked column, ties broken at random (the current column can win). If the conflict count has not reached a new low for max(200, 20 N) repairs, the run restarts from a fresh greedy start.

How these were chosen: The annealing temperatures (2.0 down to 0.05) and run length (60 N, with a floor of 200) are fixed choices, not tuned. Cooling is geometric, so every run spends the same factor of temperature. The greedy start's 4,096 tries and the rejection threshold of 4,000 favour speed. The docstring records that the greedy start leaves about 10 conflicts at every size from 1,000 to 1,000,000 queens, and that repairs then take 26 to 87 steps. The restart rule max(200, 20 N) is also a fixed choice. The server's largest sizes are the ones a request can finish within its 2-second budget, not benchmark results. No parameter sweep is committed for any agent.
