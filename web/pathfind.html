HOW IT WORKS

Every search keeps a frontier of cells it has found but not yet expanded, and expands one cell at a time. The seven racers differ only in how they choose the next cell. All of them run on the same map, with the same neighbour order and the same tie-breaking, so the counts are directly comparable.

Breadth-first (BFS)

New to this? Explore in rings: first every cell one step from the start, then every cell two steps away, and so on. The first time you reach the goal is the shortest route in steps.

A first-in, first-out queue. It is optimal when every step costs the same. On swamp, it still returns the fewest steps, which can be an expensive path.

Depth-first (DFS)

New to this? Pick a road and follow it as far as it goes, then back up to the last fork. It is quick to write and uses little memory, but the first route it finds is rarely the shortest.

A last-in, first-out stack. The path is whatever branch reached the goal first, so it is not optimal in general.

Uniform cost (Dijkstra)

New to this? Always expand the cell that is cheapest to reach from the start so far. Swamp makes some roads dearer, so it goes around them. It is slow to aim: it spreads evenly in every direction.

Priority is g, the cost from the start. Optimal for any positive costs. The lab uses it as the reference: its cost is the optimum every other path is compared with.

Greedy best-first

New to this? Head for the goal as if the map were empty: always expand the cell that looks closest to the goal by the heuristic. Very fast, but it can walk into a dead end and back out.

Priority is h alone. Not optimal: it ignores the cost already paid and the terrain entirely, so it will walk straight through swamp if that is the shortest-looking way.

A* (the workhorse)

New to this? A* balances the cost already paid (g) against the estimate of what remains (h). Its priority is f = g + h, so it expands the cells that look best overall, and it can still find the cheapest route.

Optimal when h never overestimates the true remaining cost. Each cell it expands has f no bigger than the optimal cost, so the search never wanders into routes that are already too expensive.

Weighted A* (w)

New to this? A* with a bias toward the goal. Priority is g + w·h. A bigger w is greedier: fewer cells are expanded, and the route may be a little longer.

With an admissible h, its path costs at most w times the optimum. The default is w = 2: the bound is loose enough to save many expansions on big mazes, and a route is never more than twice the best one. w = 1 is plain A*.

Bidirectional BFS

New to this? Start two searches, one from the start and one from the goal, and stop when their frontiers touch. Two small circles of search can cover far less map than one big one.

Each side is a BFS, and the side with the smaller next level expands that whole level first. It finds the fewest steps, like BFS, even with diagonals. It counts steps, not terrain cost, so it is not optimal on swamp. The search keeps going after the first meeting until no shorter route can exist.

Heuristics: admissible and consistent

Admissible means h never overestimates the true remaining cost; that is what makes A* optimal. Consistent (monotone) means h(n) ≤ cost(n, n′) + h(n′) for every step, so a cell is never reopened once expanded. Every terrain cost is at least 1, so the estimates below use a unit cost per cell.

The lab uses octile by default. With diagonal moves off, Manhattan is the tightest admissible choice; with diagonals on, octile is. Manhattan with diagonals still runs, and the leaderboard marks any path it makes suboptimal.
