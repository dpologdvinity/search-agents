HOW IT WORKS

A rover must travel between two cells of a grid, but it does not know where the walls are. A sensor reveals the walls near it, and each new wall can make the planned route wrong. A planner is the algorithm that chooses the route. This page runs two planners on the same sensor readings. D* Lite keeps the results of its earlier search and repairs only the part of the search that a new wall affects. A* forgets everything and searches again from the rover's cell. A sensor reading that changes the belief triggers a replan. Both planners always report a shortest route for what the rover knows, so their costs match at every replan. What differs is the work they do.

The map, the belief and the sensor

The map is an n × n grid of cells, numbered row by row from 0 in the top-left corner to n × n − 1 in the bottom-right corner. Cell c lies in row ⌊c / n⌋ and column c mod n. The rover starts in cell 0, and the goal is cell n × n − 1. The true walls belong to the simulation, and the rover never reads them directly.12

The rover keeps a belief, its own record of which cells are walls. An unseen cell is planned as free, which is the optimistic choice: a cell becomes a wall in the belief only after the sensor has covered it.3 The sensor covers a square of cells around the rover, with half-width R (the sensor radius, 1 to 4, default 2). The square is clipped to the map. Each cell it covers takes its true state into the belief.4

5
S(p) = \{\, c \;\mid\; |\mathrm{row}(c) - \mathrm{row}(p)| \le R \ \text{and}\ |\mathrm{col}(c) - \mathrm{col}(p)| \le R \,\} \cap \{0, \ldots, n \cdot n - 1\}

Here p is the rover's cell, S(p) is the set of cells the sensor covers, \mathrm{row}(c) = \lfloor c / n \rfloor, and \mathrm{col}(c) = c \bmod n. Because R \ge 1, the four neighbours of the rover are always sensed. The rover therefore knows every cell it can step into, and it never walks into a wall.6

The Manhattan distance between two cells is the number of horizontal and vertical steps between them, ignoring walls. Both planners use it as a heuristic, a guess of the remaining distance that aims the search at the goal.78 On a four-connected grid with unit step costs it never overestimates, and it is consistent: moving one step changes the estimate by at most the cost of that step.

78
h(a, b) = |\mathrm{row}(a) - \mathrm{row}(b)| + |\mathrm{col}(a) - \mathrm{col}(b)|

Here a and b are cells. The planners use h(s, \text{goal}) as the estimated distance from s to the goal.

The step cost c(u, v) is the price of moving between neighbouring cells. It is 1 when neither cell is a known wall, and infinity when either one is. An infinite cost removes the edge from the search, so routes go around walls, and a route is a sequence of neighbouring cells with the fewest steps.9

9
c(u, v) = \begin{cases} 1 & \text{if neither } u \text{ nor } v \text{ is a known wall} \\ \infty & \text{otherwise} \end{cases}

The planners list the four neighbours of a cell in the fixed order N, E, S, W.10 The order is what makes ties repeatable, so the same map always produces the same route, and the JavaScript port expands the same cells.

Example. On the 21 × 21 map, cell 0 is in row 0 and column 0, and the goal, cell 440, is in row 20 and column 20. So h(0, 440) = 20 + 20 = 40.

The rover loop: sense, replan, move

Each tick of the rover loop senses first. The cells whose state differs from the belief are the changes. If there are any, both planners are told about them and both replan. The driver, the planner chosen in DRIVER, then names the next cell, and the rover moves there. The page's timer calls the same tick in a loop while RUN is on.11

Both planners always see the same changes at the same moments. Their expansion counts can therefore be compared on exactly the same sequence of beliefs. The cost check counts the replans where the two planners report different costs from the rover's cell. That count must stay at 0.12

function SENSE():
    changes ← empty list
    for each cell c in SENSOR-SQUARE(pos, radius):
        seen[c] ← true
        if walls[c] ≠ belief[c]:
            belief[c] ← walls[c]
            append (c, walls[c]) to changes
    return changes

SENSE marks every covered cell as seen. It records a change only where the true state differs from the belief. A cell that turns out to be free was already planned as free, so it needs no repair.4

The goal is checked after sensing and again after the move. The move sets done the moment the rover arrives. If the driver has no next cell, the rover waits and sets the stuck flag, and the next tick senses again.14

The cost check is a cross-check between two independent implementations. The planners are never allowed to disagree silently: the mismatch is counted and shown on the page.15

D* Lite: repairing the plan

D* Lite is an incremental shortest-path search described by Koenig and Likhachev in 2002.16 Incremental means that each search reuses the results of the previous one. D* Lite searches backwards, from the goal toward the rover. Every cell holds two values. The g value g(s) is the cost the planner currently believes it has from s to the goal. The rhs value \mathrm{rhs}(s) is a one-step lookahead, named after the right-hand side of its defining equation: the best cost reached through a neighbour.17

1819
\mathrm{rhs}(s) = \begin{cases} 0 & \text{if } s = \text{goal} \\ \min\limits_{s' \in N(s)} \bigl[\, c(s, s') + g(s') \,\bigr] & \text{otherwise} \end{cases}

Here N(s) is the set of neighbours of s. A cell is consistent when g(s) = \mathrm{rhs}(s). Every g starts at infinity, except that the goal starts with rhs 0, so the first search grows outward from the goal.2018 When every cell is consistent, the rover can read off its route. From its cell pos, the next cell is the neighbour that minimises the step cost plus the g value.

21
\mathrm{next}(pos) = \arg\min_{s' \in N(pos)} \bigl[\, c(pos, s') + g(s') \,\bigr]

A new wall makes some rhs values wrong. Only those cells need work. Each one that disagrees with its g is placed on a priority queue, a heap that returns the entry with the smallest key first. The key of a cell is a pair of numbers, compared first component first.22

22
k(s) = \bigl(\, \min(g(s), \mathrm{rhs}(s)) + h(s_{\text{start}}, s) + km,\;\; \min(g(s), \mathrm{rhs}(s)) \,\bigr)

Here s_{\text{start}} is the rover's current cell, and h is the Manhattan distance. The first component estimates the total route cost through s, measured from the rover. The second breaks ties. The offset km is what lets the keys stay valid while the rover moves. It is updated at each repair from the rover's cell at the last repair, s_{\text{last}}, to its current cell.23

24
km \leftarrow km + h(s_{\text{last}}, s_{\text{start}}), \qquad s_{\text{last}} \leftarrow s_{\text{start}}

Without this offset, every key would go stale as the rover moved, and the queue would have to be rebuilt. Because the new offset is measured from the same cell the old keys were measured from, the keys already in the queue remain comparable without being rewritten.

The ON-CHANGE procedure below shows the whole repair. For each changed cell, the cell and each of its neighbours are re-examined, since every edge touching the change has a new cost. COMPUTE-SHORTEST-PATH then pops cells until the rover's cell is consistent and nothing cheaper is queued. A cell with g above rhs is overconsistent: its g is lowered to rhs, and its neighbours are re-examined. A cell with g below rhs is underconsistent: its g is set to infinity, which discards the stale value, and then the cell and its neighbours are re-examined. Cells that the change does not reach are never touched.25

26 
function D-STAR-LITE.ON-CHANGE(changes, pos):
    km ← km + h(s_last, pos)                 # the rover moved, so the keys are offset
    s_last ← pos
    s_start ← pos
    record the changed walls in the belief
    for each changed cell c:
        UPDATE(c)
        for each neighbour s of c:
            UPDATE(s)                        # the edge costs around c have changed
    COMPUTE-SHORTEST-PATH()

function UPDATE(u):
    if u is not goal:
        rhs(u) ← min over neighbours s of c(u, s) + g(s)
    if g(u) ≠ rhs(u):
        queue u with key KEY(u)
    else:
        remove u from the queue

function COMPUTE-SHORTEST-PATH():
    while the cheapest queued key is below KEY(s_start) or g(s_start) ≠ rhs(s_start):
        u ← the cell with the cheapest key
        if g(u) > rhs(u):                    # overconsistent
            g(u) ← rhs(u)
            for each neighbour s of u:
                UPDATE(s)
        else:                                # underconsistent
            g(u) ← infinity
            for each neighbour s of u:
                UPDATE(s)
            UPDATE(u)
function D-STAR-LITE.ON-CHANGE(changes, pos):
    km ← km + h(s_last, pos)
    s_last ← pos
    s_start ← pos
    for each (cell, wall) in changes:
        belief[cell] ← wall
    for each (cell, wall) in changes:            # both ends of every changed edge
        UPDATE(cell)
        for each s in NEIGHBOURS(cell):          # N, E, S, W
            UPDATE(s)
    COMPUTE-SHORTEST-PATH()

function UPDATE(u):
    if u is not goal:
        rhs(u) ← min over s in NEIGHBOURS(u) of c(u, s) + g(s)
    if ver[u] ≠ 0:
        ver[u] ← 0                               # drop the old queue entry
    if g(u) ≠ rhs(u):
        INSERT(u, KEY(u))

function KEY(u):
    m ← min(g(u), rhs(u))
    return (m + h(s_start, u) + km, m)

function INSERT(u, key):
    version ← version + 1
    ver[u] ← version
    push (key, u, version) onto the heap

function TOP():
    while the heap is not empty and ver[cell of heap top] ≠ version of heap top:
        pop the heap                             # a stale entry, skipped
    if the heap is empty:
        return (infinity, infinity)
    return the key of the heap top

function POP():
    while True:
        (k1, k2, u, v) ← pop the heap
        if ver[u] = v:
            ver[u] ← 0
            return ((k1, k2), u)

function COMPUTE-SHORTEST-PATH():
    last_expanded ← empty list
    while True:
        top ← TOP()
        if the heap is empty:
            break
        if not (top < KEY(s_start) or rhs(s_start) ≠ g(s_start)):
            break
        (k_old, u) ← POP()
        expansions ← expansions + 1
        append u to last_expanded
        k_new ← KEY(u)
        if k_old < k_new:
            INSERT(u, k_new)                     # the key was measured from older values: requeue
        else if g(u) > rhs(u):                  # overconsistent
            g(u) ← rhs(u)
            for each s in NEIGHBOURS(u):
                UPDATE(s)
        else:                                    # underconsistent
            g(u) ← infinity
            for each s in NEIGHBOURS(u):
                UPDATE(s)
            UPDATE(u)

Lazy deletion keeps the heap cheap. A queued cell cannot be removed from the middle of a heap quickly, so removing it only sets its version to 0. Each heap entry carries the version it was pushed with, and an entry is live only if that version still matches. TOP and POP discard the stale entries when they reach the top.2728

A cell can be queued more than once, and only its latest version counts. A repeated push is the normal way a key is refreshed. When POP finds a key that is smaller than the key the cell now has, the key was measured from an older rover position or an older offset, so the cell is requeued with its current key instead of being processed.29

Example. On an empty 21 × 21 map the shortest route from cell 0 to the goal has 40 steps, so g(0) = 40. The initial plan on that map expands 441 cells, the whole grid, as the results table shows.

A*: the baseline that searches from scratch

A* is a best-first search. It expands the queued cell with the lowest f = g + h, where g is the cost found so far from the rover's cell and h is the Manhattan distance to the goal. An expansion is one cell taken off the queue and processed. The search relaxes each neighbour that is not a wall. A neighbour that can be reached more cheaply through the current cell gets a new g and a new parent link.30

30
g(v) \leftarrow \min\bigl(g(v),\; g(u) + 1\bigr), \qquad f(v) = g(v) + h(v, \text{goal})

Here u is the cell being expanded, v a neighbour of u, and g(u) + 1 the cost through u, since every step costs 1. The queue orders entries by the triple (f, h, cell). Ties on f go to the cell with the smaller h, which is closer to the goal, and then to the lower cell number. That order makes every run repeat exactly.31

With a consistent heuristic, the first time a cell is expanded its cost is final. The search therefore skips a cell when a later, worse queue entry for it is popped, and it never reopens an expanded cell.32

When the sensor changes the belief, A* writes the changes and searches again from the rover's cell, without using its earlier search at all. Between changes the rover follows the stored path. The path is trimmed to start at the rover's cell after each move.33

34 
function A-STAR.ON-CHANGE(changes, pos):
    record the changed walls in the belief
    g(pos) ← 0
    queue pos with key (h(pos, goal), h(pos, goal))
    while the queue is not empty:
        u ← the queued cell with the smallest key (f, h)
        if u is goal:
            return the path from pos to goal through parent links
        for each neighbour v of u that is not a wall:
            if g(u) + 1 < g(v):
                g(v) ← g(u) + 1
                parent(v) ← u
                queue v with key (g(v) + h(v, goal), h(v, goal))
    return no path
function A-STAR.ON-CHANGE(changes, pos):
    for each (cell, wall) in changes:
        belief[cell] ← wall
    PLAN(pos)

function PLAN(pos):
    g(c) ← infinity for every cell c
    g(pos) ← 0
    parent(c) ← none for every cell c
    closed(c) ← false for every cell c
    h0 ← h(pos, goal)
    heap ← [(h0, h0, pos)]                        # entries are (f, h, cell)
    order ← empty list
    while the heap is not empty:
        (f, h, u) ← pop the heap
        if closed[u]:
            continue                              # a later, worse entry for a cell already expanded
        closed[u] ← true
        expansions ← expansions + 1
        append u to order
        if u = goal:
            break
        for each v in NEIGHBOURS(u):              # N, E, S, W
            if belief[v] is a wall:
                continue
            ng ← g(u) + 1
            if ng < g(v):
                g(v) ← ng
                parent(v) ← u
                hv ← h(v, goal)
                push (ng + hv, hv, v) onto the heap
    last_expanded ← order
    if not closed[goal]:
        path ← empty list
        return path
    path ← [goal]
    cur ← goal
    while cur ≠ pos:
        cur ← parent(cur)
        append cur to path
    reverse path
    return path

The closed flag marks an expanded cell. The check at the top of the loop is what makes the first expansion final: a later queue entry for the same cell is a worse copy and is dropped.32

The parent link of each cell records the cell it was reached from. Once the goal is closed, the path is read backwards by following parent links from the goal to the rover's cell, and then reversed. If the goal was never closed, the path is empty and the planner reports no route.35

Example. On the empty 21 × 21 map, every cell lies on some shortest route, so every f equals 40. The tie-break on h then drives the search straight to the goal. The first search expands 41 cells, the figure in the results table.

Random maps and reachability

The map is drawn from a seed, the number that starts a pseudo-random sequence. The same size, density and seed always give the same map. The generator is mulberry32, a 32-bit pseudo-random number generator. Its arithmetic is written so that the Python and JavaScript versions produce the same bits, which the parity tests check.3637

38
\begin{aligned} a &\leftarrow (a + \mathtt{0x6D2B79F5}) \bmod 2^{32} \\ t_1 &= \bigl((a \oplus (a \gg 15)) \cdot (1 \lor a)\bigr) \bmod 2^{32} \\ t_2 &= \bigl((t_1 + ((t_1 \oplus (t_1 \gg 7)) \cdot (61 \lor t_1) \bmod 2^{32})) \bmod 2^{32}\bigr) \oplus t_1 \\ u &= \bigl((t_2 \oplus (t_2 \gg 14)) \bmod 2^{32}\bigr) / 2^{32} \end{aligned}

Here a is the generator's state, \oplus is bitwise exclusive-or, \gg is a right shift, \lor is bitwise or, and u is the output, a number in [0, 1). Each draw advances the state once and returns one value u.

A cell other than the two corners is a wall when its draw is below the density. The corners are kept open, so the start and the goal are always free.39

39
\mathrm{wall}(c) = \begin{cases} 1 & \text{if } c \notin \{0,\ n \cdot n - 1\} \text{ and } u_c < \text{density} \\ 0 & \text{otherwise} \end{cases}

Here u_c is the next draw from the generator, and \text{density} is the share of walls chosen on the page, 0.1, 0.2 or 0.3. A map is drawn again from the same stream until a plain breadth-first search finds a route from the start to the goal, so the rover always has a possible route.4041

42 
function GENERATE(n, density, seed):
    while True:
        for each cell c that is not a corner:
            if the next random number < density:
                wall(c) ← 1
        if the goal is reachable from the start:
            return the walls
function GENERATE(n, density, seed):
    start ← 0
    goal ← n * n − 1
    rng ← MULBERRY32(seed)
    while True:
        walls ← n * n cells, all free
        for c in 0 to n * n − 1:
            if c ≠ start and c ≠ goal and rng.NEXT() < density:
                walls[c] ← 1
        if REACHABLE(n, walls, start, goal):
            return walls

function REACHABLE(n, walls, start, goal):
    seen ← n * n cells, none seen
    seen[start] ← 1
    queue ← [start]
    while the queue is not empty:
        u ← the first cell in the queue, removed
        if u = goal:
            return true
        for each v in NEIGHBOURS(u):
            if not seen[v] and not walls[v]:
                seen[v] ← 1
                append v to the queue
    return false

The redraw is part of the same stream. A map that fails the test is not reseeded: the next draws continue from where the failed draw stopped. The page and the CLI therefore draw the same map for the same arguments.43

REACHABLE is a breadth-first search: it visits cells in the order they are discovered, so it finds a route if one exists, and it stops as soon as the goal is reached.41 The generator's docstring notes that redraws are rare at the densities the page offers.44

The benchmark explores each map twice, once steered by D* Lite and once by A*. In both runs, both planners see the same belief changes, so the work of each planner is measured on the same route.45 Each row averages 5 seeded maps.46 A map's work splits into the initial plan on the empty map, I, and the replans after sensing, R, so the total is T = I + R.47 The table reports the averages of those totals, and the ratio is the D* Lite average divided by the A* average.

Each row is the average over 5 seeded maps, with the sensor radius at its default of 2. The initial plan depends only on the size, because both planners start on the empty map. The D* Lite initial plan expands n × n cells in every row, the whole grid. The search runs until the start cell is consistent and nothing cheaper is queued.49 The start is the cell farthest from the goal, so the search has to cover the whole grid before that test passes. The replans make up the rest of the work.50

Two results stand out. First, after the initial plan, D* Lite's replan expansions are far below A*'s at every size and density. Second, the total favours D* Lite only at 20% and 30% walls. At 10% walls the one-off initial plan costs more than the replans save, and D* Lite does more work in all three sizes, with ratios of 1.11, 1.28 and 1.21.50

Time is measured as wall-clock time spent inside each planner, in pure Python on one core. Per expansion, D* Lite takes about 3 to 7 times as long as A* in every row, because each D* Lite expansion does more bookkeeping: keys, heap entries and version checks. So fewer D* Lite expansions do not always mean less time: at 61 × 61 and 30% walls, D* Lite took 182 ms against A*'s 68 ms, though D* Lite did about half as many expansions.51

Reading the counters

Every expansion so far is counted, including the initial plan on the empty map. The chart plots the cumulative count against the rover's steps for each planner, and the lower line has done less work. REPLANS counts the ticks on which the sensor changed something.60

The HEAT MAP colours each cell by D* Lite's g or rhs, from cyan near the goal to pink far from it. Cells with an infinite value are left uncoloured. Green outlines mark the cells expanded by the last replan of the planner chosen in ROUTE SHOWN, and they fade after about 1.4 seconds.61
