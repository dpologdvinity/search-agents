HOW IT WORKS

A policy is a rule that picks an action from the current state. This page compares five policies on the cart-pole task: a coin flip, a hand-tuned PD controller, and three policies that learn from reward alone, which is a number the environment gives after each step. The learned ones are REINFORCE with a baseline, an actor-critic, and a cross-entropy search. The two gradient-trained policies are small networks with one hidden layer of 16 tanh units (tanh is a function that squashes each value into (−1, 1)), and every gradient, the direction in which a parameter should move to raise the score, is written out by hand in NumPy. The cross-entropy rule is a single linear function of the state.

The physics

The cart-pole system is a cart on a track with a pole hinged to its top. At each control step the agent chooses an action, left or right, and the cart is pushed with a force of 10 N. A control step lasts 0.02 s, so the simulation runs at 50 Hz. The state has four numbers: the cart position x and velocity \dot x, and the pole angle \theta and angular velocity \dot\theta. The angle is measured from vertical in radians, and a positive angle leans the top of the pole to the right, so a push to the right corrects a pole that leans right.1

The equations are the classic cart-pole equations with the constants of gym's CartPole.2 At each step, the force on the cart is F = +10 N for a push to the right and -10 N for a push to the left.

\begin{aligned} \text{temp} &= \frac{F + m_p\, l\, \dot\theta^{2} \sin\theta}{M} \\ \ddot\theta &= \frac{g \sin\theta - \cos\theta \cdot \text{temp}}{l\left(\frac{4}{3} - \frac{m_p \cos^{2}\theta}{M}\right)} \\ \ddot x &= \text{temp} - \frac{m_p\, l\, \ddot\theta \cos\theta}{M} \end{aligned}
345

Here g = 9.8 m/s² is gravity, m_c = 1.0 kg is the cart mass, m_p = 0.1 kg is the pole mass, M = m_c + m_p = 1.1 kg is the total mass, and l = 0.5 m is the distance from the hinge to the pole's centre of mass. The value \text{temp} is the cart's acceleration that the push alone would produce. The pole's angular acceleration \ddot\theta couples gravity against the cart's acceleration, and the cart's acceleration \ddot x is then corrected for the reaction of the pole. The factor 4/3 is the moment of inertia of a rod about its end.6

The state is advanced by the explicit Euler method, which moves each variable by its rate times the time step \tau = 0.02 s, using the rates from the start of the step.7

x \leftarrow x + \tau\,\dot x, \qquad \dot x \leftarrow \dot x + \tau\,\ddot x, \qquad \theta \leftarrow \theta + \tau\,\dot\theta, \qquad \dot\theta \leftarrow \dot\theta + \tau\,\ddot\theta
8

At the start of an episode each of the four state variables is drawn uniformly from [-0.05, 0.05].9 The episode is terminated when the pole falls or the cart leaves the track, and is truncated when it reaches the 500-step cap without falling.10

\text{terminated} \iff |x| > 2.4 \;\lor\; |\theta| > 12^\circ \;(0.2094 \text{ rad}), \qquad \text{truncated} \iff \lnot\,\text{terminated} \land \text{steps} \ge 500
11

Every step gives reward r = 1.12 The total reward of an episode is therefore the number of steps balanced, and a truncated episode counts as a full balance of 500.

Example. Start from \theta = 0.05 rad with the other three values at zero, and push right. Then \text{temp} = 9.09, \ddot\theta = -13.82 rad/s² and \ddot x = 9.72 m/s². After one step, \dot x = 0.194 m/s and \dot\theta = -0.276 rad/s. The angular acceleration is negative, so the pole starts to swing back toward vertical.

13 
function STEP(state, action):
    force ← +FORCE if action is RIGHT, otherwise −FORCE
    temp ← (force + POLE-MASS-LENGTH · theta_dot² · sin(theta)) / TOTAL-MASS
    theta_acc ← (GRAVITY · sin(theta) − cos(theta) · temp) / (HALF-LENGTH · (4/3 − MASS-POLE · cos(theta)² / TOTAL-MASS))
    x_acc ← temp − POLE-MASS-LENGTH · theta_acc · cos(theta) / TOTAL-MASS
    x, x_dot, theta, theta_dot ← x + TAU · x_dot, x_dot + TAU · x_acc, theta + TAU · theta_dot, theta_dot + TAU · theta_acc
    terminated ← abs(x) > X-LIMIT or abs(theta) > THETA-LIMIT
    return state, reward 1, terminated
constants: GRAVITY = 9.8, MASS-CART = 1.0, MASS-POLE = 0.1, TOTAL-MASS = 1.1, HALF-LENGTH = 0.5,
           POLE-MASS-LENGTH = 0.05, FORCE = 10.0, TAU = 0.02, THETA-LIMIT = 0.2094 (12 degrees), X-LIMIT = 2.4, MAX-STEPS = 500

function STEP(state, action):
    if terminated or truncated:
        raise error "call RESET first"
    force ← +FORCE if action is RIGHT, otherwise −FORCE
    cos_t ← cos(theta)
    sin_t ← sin(theta)
    temp ← (force + POLE-MASS-LENGTH · theta_dot · theta_dot · sin_t) / TOTAL-MASS    # force on the cart, with the centripetal term
    theta_acc ← (GRAVITY · sin_t − cos_t · temp) / (HALF-LENGTH · (4/3 − MASS-POLE · cos_t · cos_t / TOTAL-MASS))
    x_acc ← temp − POLE-MASS-LENGTH · theta_acc · cos_t / TOTAL-MASS                 # cart acceleration after the pole's reaction
    x ← x + TAU · x_dot                    # positions first, with the velocities from the start of the step
    x_dot ← x_dot + TAU · x_acc
    theta ← theta + TAU · theta_dot
    theta_dot ← theta_dot + TAU · theta_acc
    steps ← steps + 1
    terminated ← abs(x) > X-LIMIT or abs(theta) > THETA-LIMIT
    truncated ← (not terminated) and steps ≥ MAX-STEPS
    return state, reward 1, terminated, truncated

Explicit and semi-implicit Euler. Both position updates use the velocities from before the step, which makes the scheme explicit. A semi-implicit scheme would use the new velocity in the position update. The code keeps the old values on purpose, so each line uses the same state.7

Reading the state once. The sine and cosine of the angle are read once, before any variable changes. Every formula in the step therefore sees the state at the start of the step.14

PD controller (hand-tuned)

A PD controller corrects an error in proportion to the error (the P term) and in proportion to its rate of change (the D term). This one does not learn. Its four gains were set by hand. It computes a signed control value u and pushes right when u > 0, and left otherwise.15

u = 30\,\theta + 6\,\dot\theta + 0.1\,x + 0.5\,\dot x, \qquad \text{action} = \begin{cases} \text{RIGHT} & \text{if } u > 0 \\ \text{LEFT} & \text{otherwise} \end{cases}
16

The first two terms, on the angle and its rate, keep the pole upright. The last two, on the cart position and velocity, steer the cart back toward the middle of the track. Example. At \theta = 0.05 rad with the other values at zero, u = 30 \times 0.05 = 1.5 > 0, so the controller pushes right.

1516 
function PD-ACT(state):
    u ← 30 · theta + 6 · theta_dot + 0.1 · x + 0.5 · x_dot     # signed control value
    if u > 0:
        return RIGHT
    return LEFT
constants: K = (30, 6, 0.1, 0.5)                  # gains on (theta, theta_dot, x, x_dot), set by hand

function PD-ACT(state):
    x, x_dot, theta, theta_dot ← state
    u ← K[1] · theta + K[2] · theta_dot + K[3] · x + K[4] · x_dot    # the control value, before its sign is taken
    if u > 0:
        return RIGHT                                           # push toward the lean
    otherwise:
        return LEFT

Random (the floor)

The random agent chooses left or right with equal probability at each step. It has no model and no memory, so it sets the floor that any real controller should beat. It averages 22.5 steps before the pole falls.17

17 
function RANDOM-ACT(rng):
    return LEFT or RIGHT, each with probability 1/2

The networks

Before a network reads a state, each variable is multiplied by a fixed factor so that values lie roughly in [-1, 1]. The cart position is divided by 2.4, the cart and pole velocities by 2, and the angle by 0.2094 rad (12 degrees). The factors are fixed rather than learned, so the browser applies the same numbers.18

s = \left(\frac{x}{2.4},\; \frac{\dot x}{2},\; \frac{\theta}{0.2094},\; \frac{\dot\theta}{2}\right)
19

A multilayer perceptron (MLP) with one hidden layer is a function of s. Its hidden layer applies a tanh function, which squashes each value into (-1, 1), and its output layer is linear.20

h = \tanh(W_1 s + b_1), \qquad z = W_2 h + b_2
21

Here W_1 is a 16 \times 4 matrix and b_1 a vector of 16 biases, so h has 16 hidden activations. For the policy, W_2 is 2 \times 16, and z = (z_0, z_1) are the two logits, one for left and one for right. A softmax turns them into probabilities, and the policy is the pair p_L = e^{z_0} / (e^{z_0} + e^{z_1}) and p_R = 1 - p_L.22

The policy acts greedily by choosing right when z_1 > z_0, which is the same as p_R > 0.5. During training it samples from p instead, so it keeps exploring.2324

The critic is a second MLP with one output, which is the value estimate V(s) of a state. Its output is multiplied by 50 (the constant VALUE_SCALE), so the network predicts V / 50 and its outputs stay near 1 when values approach 100.2526

Starting weights. The hidden weights start at random values with standard deviation 1/\sqrt{4} and the output weights at standard deviation s/\sqrt{16}, where s is the output scale. The output scale is 0.1 for the policy, so the first policy is close to 50/50, and 1.0 for the critic. All biases start at zero.2728

Backpropagation is the chain rule applied layer by layer. Given dL/dZ for each row of a batch, where a row is one step, the gradients are:

dW_2 = dZ^{\top} H, \qquad db_2 = \sum_{\text{rows}} dZ, \qquad dH = dZ\, W_2, \qquad dA = dH \odot (1 - H^{2}), \qquad dW_1 = dA^{\top} X, \qquad db_1 = \sum_{\text{rows}} dA
29

Here X is the matrix of scaled states with one row per step, H the matrix of hidden activations, \odot the elementwise product, and 1 - H^2 the derivative of tanh. The tests compare these gradients with finite differences.30

Adam is the optimiser used for every network. It keeps a running mean m of each gradient g and a running mean v of its square. The update for each parameter \theta is:

m \leftarrow \beta_1 m + (1 - \beta_1)\,g, \qquad v \leftarrow \beta_2 v + (1 - \beta_2)\,g^{2}, \qquad \theta \leftarrow \theta - \alpha\, \frac{m / (1 - \beta_1^{t})}{\sqrt{v / (1 - \beta_2^{t})} + \varepsilon}
31

The step size is \alpha = 0.01, the decay rates are \beta_1 = 0.9 and \beta_2 = 0.999, and \varepsilon = 10^{-8} guards the division. The step count is t. Dividing by 1 - \beta^{t} corrects for both averages starting at zero, which would otherwise make the first steps too small. The step subtracts the update, so the gradient passed in is the gradient of the loss, and the step lowers it.32

33 
function ADAM-STEP(grads):
    t ← t + 1
    for each parameter p with gradient g:
        m ← 0.9 · m + 0.1 · g                  # running mean of the gradient
        v ← 0.999 · v + 0.001 · g²             # running mean of its square
        p ← p − 0.01 · (m / (1 − 0.9^t)) / (√(v / (1 − 0.999^t)) + 1e-8)
constants: LR = 0.01, BETA1 = 0.9, BETA2 = 0.999, EPS = 1e-8

function ADAM-STEP(grads):
    t ← t + 1
    c1 ← 1 − BETA1^t
    c2 ← 1 − BETA2^t
    for each parameter p with gradient g:
        m ← BETA1 · m + (1 − BETA1) · g
        v ← BETA2 · v + (1 − BETA2) · g · g
        p ← p − LR · (m / c1) / (√(v / c2) + EPS)              # the step lowers the loss

REINFORCE with a baseline

REINFORCE is a policy gradient method. It samples episodes from the policy, then makes the actions that led to high returns more likely. An episode is a sequence of states, actions and rewards. The return G_t is the discounted sum of the rewards from step t on, where the discount factor \gamma = 0.99 makes later rewards count a little less. It is computed backwards, one step at a time.3435

G_t = r_t + \gamma\, G_{t+1}, \qquad G_{T} = 0
36

The baseline is the mean of the returns over every step of the batch of 8 episodes. Subtracting a baseline does not change the expected gradient, but it lowers the variance of the estimate. The advantage A_t is the return minus the baseline, divided by the batch standard deviation \sigma_G (the population form, which divides by the number of steps T), so that the size of the step does not depend on the reward scale.37

A_t = \frac{G_t - \bar G}{\sigma_G + 10^{-8}}
38

Here \bar G and \sigma_G are taken over all T steps of the batch, and the term 10^{-8} keeps the division safe when every return is the same.

The loss is L = -\frac{1}{T}\sum_t A_t \log \pi(a_t \mid s_t), the negative of the advantage-weighted log-probability of each action taken. Minimising it performs gradient ascent on the expected return. For a softmax, the derivative with respect to each logit is:

\frac{\partial L}{\partial z_k} = -\frac{A_t}{T}\left(\mathbf{1}[k = a_t] - p_k\right)
39

Here \mathbf{1}[k = a_t] is 1 when k is the action taken and 0 otherwise, and p_k is the policy's probability of k. This row of derivatives is the dZ that backpropagation takes, and then one Adam step is taken on the batch. Each batch of 8 episodes gives one update, with a learning rate of 0.01.4041

Example. In a batch where the action taken had a return above the mean, A_t is positive, and the derivative for the chosen logit is negative, so Adam raises that logit. The opposite holds for a below-average action.

42 
function ROLLOUT(policy, rng, env_seed):
    state ← RESET(env_seed)                  # the start state comes from the seed
    while the episode is not done:
        s ← scaled(state)
        p_left ← probability of LEFT from policy(s)
        action ← LEFT if a random number is below p_left, otherwise RIGHT
        state ← STEP(state, action)
        record s, action, reward 1, and scaled(state)
    return the episode
function ROLLOUT(policy, rng, env_seed):
    env ← a new CART-POLE seeded with env_seed
    o ← RESET(env_seed)
    obs, act, rew, nxt ← empty lists
    while not (terminated or truncated):
        x ← scaled(o)                                  # normalised observation the agent sees
        Z ← policy forward pass on x                   # two logits
        p_left ← softmax(Z)[LEFT]
        a ← LEFT if rng.random() < p_left, otherwise RIGHT
        o, r, _, _ ← STEP(env, a)                       # r is always 1
        append x to obs, a to act, r to rew, scaled(o) to nxt
    return Episode(obs, act, rew, nxt, terminated)

Sampling, not the argmax. The rollout draws each action from the policy's probabilities. The greedy rule is used only when the trained policy is shown or benchmarked. Each episode in a batch gets its own start state, drawn from the training generator, so the batch covers different starts.43

function REINFORCE-UPDATE(batch):           # 8 sampled episodes
    G ← discounted return of every step in the batch
    advantage ← (G − mean(G)) / (std(G) + 1e-8)         # the batch mean is the baseline
    loss ← −mean(advantage · log π(action | state))
    take one ADAM step that lowers loss
constants: GAMMA = 0.99, BATCH = 8, LR = 0.01, EPS = 1e-8

function REINFORCE-UPDATE(batch):                    # batch holds BATCH sampled episodes
    X ← scaled observations of every step, one row per step
    A ← actions of every step
    G ← empty array of length T
    for each episode in batch:
        g ← 0
        for t from the last step of the episode back to the first:
            g ← r_t + GAMMA · g                        # discounted return, computed backwards
            G[t] ← g
    adv ← (G − mean(G)) / (std(G) + EPS)              # mean and population std over all T steps
    POLICY-STEP(X, A, adv)

function POLICY-STEP(X, A, adv):
    H, Z ← FORWARD(X)                                   # tanh hidden activations and logits
    P ← softmax(Z), row by row
    dZ ← −(adv / T) · (onehot(A) − P)                  # dL/dZ for each row
    grads ← BACKPROP(X, H, dZ)                          # dW2, db2, dW1, db1
    ADAM-STEP(grads)

Why the update uses a batch. A single episode gives a noisy gradient, and a batch of 8 gives a steadier one. The baseline is taken over the whole batch, so it does not depend on any one episode. The gradient is divided by the total number of steps T, so it is an average per step, and a long episode contributes more terms because it has more steps.37

Why the gradient is written out. The project keeps training in NumPy so that serving needs no deep-learning framework. The derivatives are therefore written out by hand, and each line can be checked against the equations above. The tests check them numerically.4546

Actor-critic (Monte Carlo critic)

Actor-critic adds a learned critic to the policy. The policy is the actor. The critic is trained to predict the return from each state, which is the value V(s). The advantage is then the return that the episode actually earned minus the critic's prediction, so the policy learns how much better or worse the episode went than the critic expected, not how it compared with the batch average.47

The critic's target is the Monte Carlo return y_t = G_t, which is the return actually observed from step t to the end of the episode. The critic minimises a squared error, and its advantage is computed from the same values before the critic moves.48

L_V = \frac{1}{2T}\sum_t \bigl(V(s_t) - y_t\bigr)^2, \qquad V(s_t) = 50\, z^{V}_t, \qquad \delta_t = y_t - V(s_t), \qquad A_t = \frac{\delta_t}{50}
49

Here z^{V}_t is the critic's raw output for step t, and the policy then takes the same update as REINFORCE with advantage A_t. The division by 50 brings \delta_t to roughly the scale of a return minus a baseline, so the step size stays comparable with REINFORCE's. The critic's gradient is \partial L_V / \partial z^{V}_t = 50\,(V(s_t) - y_t)/T, and it takes one Adam step at learning rate 0.01.50

The textbook alternative is a temporal-difference target, TD(0), which bootstraps from the critic's own estimate of the next state: y_t = r_t + \gamma V(s_{t+1}), with V = 0 after a fall. In this code it is kept as the option ACTOR_CRITIC_TARGET = "td". In the pilot runs it did not learn reliably, so the shipped critic regresses onto Monte Carlo returns.51525354

55 
function ACTOR-CRITIC-UPDATE(batch):
    V ← critic's value of every step in the batch
    y ← Monte Carlo return of every step
    take one ADAM step on the critic that lowers ½ · mean((V − y)²)
    delta ← y − V                                        # the critic's error is the advantage
    POLICY-STEP(X, A, delta / 50)                        # the same policy update as REINFORCE
constants: GAMMA = 0.99, VALUE_SCALE = 50, CRITIC_LR = 0.01, ACTOR_CRITIC_TARGET = "mc"

function ACTOR-CRITIC-UPDATE(batch):
    X ← scaled observations, one row per step
    Xn ← scaled next observations
    A ← actions
    R ← rewards, all 1
    done ← 0 for every step, except that the last step of a terminated episode is 1
    T ← number of steps in the batch
    Hv, Zv ← FORWARD(critic, X)
    V ← VALUE_SCALE · Zv                                  # critic values for each step
    if ACTOR_CRITIC_TARGET is "mc":
        y ← Monte Carlo returns of the batch, computed as in REINFORCE-UPDATE
    otherwise:                                             # "td"
        Vn ← VALUE_SCALE · critic value of Xn
        y ← R + GAMMA · Vn · (1 − done)                   # TD(0) target, treated as a constant
    dZv ← VALUE_SCALE · (V − y) / T                       # dL/dZv for L = ½ · mean((V − y)²)
    ADAM-STEP(BACKPROP(critic, X, Hv, dZv), CRITIC_LR)    # the critic moves here
    delta ← y − V                                         # from the values before the critic moved
    POLICY-STEP(X, A, delta / VALUE_SCALE)                # the policy update defined under REINFORCE

Why the advantage is taken before the critic moves. The critic's update changes V. Computing \delta_t from the old values keeps the advantage defined by the same critic that produced it, and the code does this on purpose.56

Stopping at a true fall. In the TD branch, the flag done is set only on the last step of an episode that fell. An episode cut off at 500 steps still bootstraps from the next state, because the cap is not a failure.57

Cross-entropy search

The cross-entropy method (CEM) is a search with no gradients. It samples candidate parameter vectors from a Gaussian distribution, a bell curve over each parameter with a mean \mu and a spread \sigma. It scores each candidate, keeps the best quarter as the elite, and refits the Gaussian to the elite. The policy is linear: it pushes right when w \cdot s + b > 0, where s is the scaled state, so the parameter vector \theta = (w_1, w_2, w_3, w_4, b) has five numbers.58

\theta^{(i)} = \mu + \sigma \odot \varepsilon^{(i)}, \quad \varepsilon^{(i)} \sim \mathcal{N}(0, I), \quad i = 1,\dots,40 \qquad \mu \leftarrow \frac{1}{10}\sum_{i \in E}\theta^{(i)}, \qquad \sigma \leftarrow \operatorname{std}_{i \in E}\bigl(\theta^{(i)}\bigr) + 0.01
59

Each generation draws 40 candidates. The score of a candidate is the number of steps it balances from one start state, shared by all 40 candidates, so they are compared on the same episode. E is the set of the 10 highest scores. Ties at the cap are broken by the sort order, so some elite choices among tied candidates are arbitrary. The mean and spread are computed separately for each of the five numbers, and the floor of 0.01 stops the spread from collapsing to zero too early. The search starts with \mu = 0 and \sigma = 1.6061

62 
function CEM(episodes):
    mu ← zeros(5)                            # mean of the sampling distribution
    sigma ← ones(5)                          # spread for each of the five numbers
    while fewer than episodes have run:
        candidates ← 40 draws of mu + sigma · standard normal noise
        env_seed ← one start state, shared by the whole generation
        scores ← steps each candidate balances on env_seed
        elite ← the 10 candidates with the highest scores
        mu ← mean of elite
        sigma ← std of elite + 0.01
    return mu
constants: DIM = 5, CEM_POP = 40, CEM_ELITE = 10, CEM_NOISE = 0.01

function CEM(episodes):
    mu ← zeros(DIM)
    sigma ← ones(DIM)
    returns ← empty list
    while length(returns) < episodes:
        thetas ← mu + sigma · standard normal draws, shape (CEM_POP, DIM)
        env_seed ← a random integer below 2^31                # one start state for the whole generation
        scores ← for each theta in thetas: steps LINEAR-ACT(theta) balances on env_seed
        append scores to returns
        elite ← the CEM_ELITE rows of thetas with the largest scores
        mu ← mean of elite over its rows
        sigma ← std of elite over its rows + CEM_NOISE        # per number, population std
    return mu

function LINEAR-ACT(theta, state):
    w ← theta[1..4]
    b ← theta[5]
    if w · scaled(state) + b > 0:
        return RIGHT
    otherwise:
        return LEFT

The TD(0) pilots are recorded as configurations in the code. Across the five configurations tried, at most one of the five seeds ended with a last-50 mean of 475 or more, so the TD(0) critic did not learn reliably and was not shipped.54 The in-browser REINFORCE trainer uses the same equations (batch 8, γ 0.99, learning rate 0.01, batch-normalised advantages) with its own random stream, so its runs will not match the Python seeds.

Training in the browser

TRAIN IN YOUR BROWSER runs 600 episodes of REINFORCE from random weights in this tab, with the same equations as the Python run. It takes one Adam step per batch of 8 episodes and draws its random numbers from a seeded generator (mulberry32), so a browser run does not reproduce a Python seed. The starting weights have the same distribution as the Python ones.6768

The browser also uses batch-normalised advantages, which divide by the population standard deviation plus 10^{-8}. The gradient, the backward pass and the Adam update are plain loops over one flat array of parameters.69

Verifying the port

The browser runs the physics and the policies in JavaScript. VERIFY AGAINST PYTHON asks the server to replay one episode in Python from the Python start state, and then checks every step in the browser. For each step it compares the action with the action Python took, and it compares the next state from the Python state with the browser's next state. The check passes when no action differs and the largest one-step error is below 10^{-9}.7071

Each step is checked from the Python state, not from the browser's own running state. The controllers hover near the switching point, so a single flipped decision would otherwise make the rest of the episode diverge, and the check would test nothing else.
